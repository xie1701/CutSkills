# 开工 / 收工 · 各一句口令

两个口令，都是一句话。**没听到口令就不动业务代码**（读文档、跑校验随时可以）。

---

## 开工 · 口令「开工」

听到「开工」，这一个工位按顺序做，做完才写第一行业务代码：

1. **读三份**：`AGENTS.md` → `docs/ai-collab/PROTOCOL.md` → `HANDOFF.md` + `TASKS.md`。
2. **认工位**：我是谁（分支前缀 `ai/<工具名>/`）、我的端口号段、我的项目副本后缀。
3. **领任务**：从 `TASKS.md` 的「未开工」里挑一个（或人指定号），**不许挑 `在跑` 的**。
4. **开分支**：`git switch master && git pull --ff-only`（无远端就跳过）→ `git switch -c ai/<工具名>/T-xxx`。
5. **落状态**：`TASKS.md` 把该行改成 `在跑`，写上工位名与时间。
6. **记对照基线**：先把「合并前要跑的完整校验」跑一遍，把当前 🟢/🟡/🔴 记下来，
   写进这一轮的开始行（**这就是你判「有没有变坏」的唯一依据**）。
7. 开工回执一句话：`T-xxx 已开跑｜分支 ai/<工具>/T-xxx｜基线 selftest 1红 / audit 11红 / 本片 26-0-0`。

> 规则 ④ 从这一刻生效：红了就是红了，不许为了绿去改产品、放宽断言、跳过用例。

---

## 收工 · 口令「收工」

听到「收工」，按顺序收，**没收完不算收工**：

1. **跑完整校验**（`PROTOCOL.md` 第四节那串），把「改前 → 改后」的数字记下来。
2. **写一行留痕**：`TASKS.md` 该行的「改了什么 + 拿什么验的」。
3. **推状态**：校验没有变坏（红黄不多）→ 改 `待复核`；变坏了 → 留在 `在跑` 并写清坏在哪。
4. **更新 `HANDOFF.md`**：分支、提交 SHA、这一版改了什么、下一位开场提示词（可粘走那种）。
5. **提交**：`git add -A && git commit -m "<任务号> <一句话>"`，推分支（有远端的话）。
6. **交接回执一句话**：
   `T-xxx 收工｜分支 ai/<工具>/T-xxx @ <sha>｜本片 26-0-0（原 26-0-0）｜selftest 1红 / audit 11红（未变多）｜待复核`。

---

## 两个口令之外

| 情况 | 怎么做 |
|---|---|
| 被卡住（缺素材、缺授权、要人拍板） | 收工，`TASKS.md` 留在 `在跑`，写「卡在哪、需要谁给什么」，HANDOFF 同写 |
| 发现别人任务相关的问题 | **不要顺手改**，在 `TASKS.md` 新开一行 `未开工` |
| 校验发现红比基线多 | 不许合并；修掉，或把任务改回 `在跑` 并写清 |
| 判据本身错了 | 单开任务改判据，写「错在哪 + 用什么负样本证明」 |
| 想用 `--force` / `--no-render` / skip | 只允许在**排查**时用，并在收工行里明说「用过，原因，结果」 |

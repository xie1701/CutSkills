# CutSkills · 同音残词 / 口吃重尾 疑似表（脚本种子，不是判决）#
# 为什么要有这张表：ASR 是声学概率模型，会给每个音节打毫秒级时间戳，却没有物理与
# 行业常识——粤语连读被听成「大约有十万米高」「我哋嘅效果好先」「生万鱼池」。
# 这类错字光靠「语料里出现过没有」判不出来（语料里本来就没有这句话），只能拿
# 一张人工维护的嫌疑表打底，再让人读上下文拍板。
#
# 格式（**制表符**分隔，别用空格——错词本身可能带空格）：
#     错词 <TAB> 建议词 <TAB> 等长|不等长 <TAB> 备注 [<TAB> 排除后接]
# 「排除后接」是可选的第五列，用 `|` 分开：错词后面紧跟这些字就不算命中。
# 为什么需要它：同一库里有「效果好好啊得噶」这种**真话**，拿「效果好」当错词
# 一刀切会把它冤枉成「效果图」（「效果好好」＝效果好+好，是正常说法）。
# 误杀比漏判更贵——被冤枉一次，下一个人才会把整张表当噪声看。
# 规矩（准绳 references/editorial-packaging-principles.md 原则 A5）：
#   · 等长：替换前后字数相同，字级时间戳不用挪，可以自动落地；
#   · 不等长：字数变了，字宽要被均摊、时间戳会漂，默认拒绝应用——词表条目必须显式
#     标 `unsafe: true`，并且调用方显式允许才落地（`lexicon.py --audit` 看得见）；
#   · 备注里写「待人工」＝这条只是怀疑，定稿必须有人读上下文再拍板
#     （「大咧」可能是「大家」，也可能是「大间」——猜错比留着更糟）；
#   · 表里命中只算「嫌疑」，定论写进 <库>/_cutskills/lexicon.json 的 `terms`。
#
# 来源：欧阳茶楼三片（dianzan-a/b/c）2026-11-13 实读 out/subs.json 与库内 ASR 转写；
# 「四大轩王」为柒造/欧阳两库既有词表案例，一并作为回归样本留着。

# 第三个裁判：换素材之后，模板还成立吗

2026-11-08 · 用柒造的真素材跑 10 秒复刻。

前两个裁判（结构对齐、视觉混洗）判的是「像不像参考片」。这个判的是另一件事：
**把模板套到没参与建模的素材上，声明的数字还落不落回带内。**
落回去，它是模板；落不回去，前面那些"拆解"就只是临摹笔记。

## 一、怎么控制变量

同一批素材、同一批字幕、同一个时间轴，**只换包装模板**。

| | 版本 A | 版本 C |
|---|---|---|
| 字幕系统 | pack-safe-talking（A 族） | pack-safe-talking（同） |
| 壳体 | 无 | pack-hud-monitor（C 族：顶条 + 角标 + 时间码） |
| 画面 | 工地 4 镜（地面打磨 / 地坪摊料 / 刮平特写 / 自流平倒料），各 2.5–2.7s | 同 |
| 声音 | 熊工口播原声 354.12–364.44（连续，跨 4 个镜头） | 同 |
| 字幕 | 词级时间戳按字切，9 条 | 同 |

两版唯一的差别是 `--shell pack-hud-monitor` 这一个参数。
素材是**从没参与过包装建模**的：20 支参考片全是录屏 / 口播 / 展厅，没有一支是工地画面。

## 二、结果

8 个能被像素量出来的 token（`scripts/measure_pack.py`，只看成片像素，不读渲染器的 JSON）：

| token | 模板声明 | A 实测 | C 实测 | 换介质：单机位口播 |
|---|---|---|---|---|
| 字幕带中心（%H） | 0.79–0.92 | **0.859** | **0.859** | **0.860** |
| 字形高度（%H，含描边） | 0.033–0.060 | **0.052** | **0.052** | **0.050** |
| 字幕下沿距底（%H） | ≥0.05 | **0.116** | **0.116** | **0.116** |
| 镜头中位（秒） | 2.0–4.8 | **2.6** | **2.6** | **2.6** |
| 音效密度（处/分） | A: 0–8.5 / C: 2.0–6.3 | **0.0** ✅ | **0.0** ❌ | **0.0** ❌ |
| 顶条高度（%H） | 0.05 | — | **0.048** | **0.048** |
| 顶条字高（%H） | 0.014 | — | **0.011** | **0.011** |
| 角标高度（%H） | 0.116–0.14 | — | **0.123** | **0.123** |

- A 版：**5/5 在带内**
- C 版：**7/8**，唯一带外的是音效
- 换介质（同一套模板 × 单机位口播，白墙亮底）：**7/8**，同一处带外

**壳是参数，不是样子。** 加一个 `--shell`，3 个 token 从"没有"变成"有且落在带内"（顶条 0→0.048、角标 无→0.123、顶条字高 →0.011），
另外 4 个字幕/节奏 token **一个数都没动**。这说明壳和字幕系统在渲染上是真的解耦的——
不是"看起来加了条"，是加了之后下面那层不受影响。

## 三、唯一没落地的那一层：声音

C 族模板写着 `sfx_density_per_min: [2.0, 6.3]`，实测 **0.0**。
这不是量错了——`render_film.py` 到今天还没实现音效（C2 一直在待办里）。

这句要写在最前面：**模板写得出来，产线还做不到。** 一个模板有 8 个数字，
产线只兑现 7 个，那 1 个就是"说得出、做不到"的部分。审计里该按 7/8 算，
而不是拿"拆解完成"当"复刻完成"。

顺带一个反例：A 族声明的音效带是 0–8.5/分，同样的 0.0 在 A 里是**合格**的。
同一个实测值，在 A 族合格、在 C 族不合格——这就是为什么要分族，而不是做一套通用参数。

## 四、分界线在哪

把这次要人做的决定逐条列出来，就看见线了：

| 模板给的（换素材仍成立） | 必须人给的（模板给不了） |
|---|---|
| 字幕带中心、字形高度、行宽上下限、下沿安全距离 | 这 10 秒选哪 4 个镜头、每支的入点几秒 |
| 顶条高度、条内字高、角标高度、常驻元素静止 | 顶条的**条目文字**、章节怎么划（来自 EDL 的 beats） |
| 镜头中位、音效密度带、每族允许的饱和度上限 | 断句断在哪个字（模板只给 8–11 字，断哪儿要读语义） |
| 描边与投影二选一、下沿不进最后 5%H | 角标写什么、时间码从几秒起 |
| — | 音效打在哪一帧（今天压根没做） |
| — | 曝光/冷暖的基调（白平衡是渲染器自动对齐的，但"要冷还是要暖"是人的选择） |

**判据一句话：**
一个数字如果是**看着参考片的某一帧**填出来的，它就是临摹；
如果它是**从这一族多支片里取的交集区间**，并且**换素材、换介质后仍落在带内**，它才是模板。

这条线不在"精度"上，在"来源"上。20 支参考片拆出来的 5 族，一共只留下 40 多个数字；
而 20 份逐支拆解加起来有 400 多条判断——**能被说成参数的是那 40 个，剩下 360 条都是临摹**。
今天的 10 秒证明的是：那 40 个里，版式这一层的 7 个真能搬走；声音那 1 个还搬不动。

## 五、今天量出来的三个坑（都是新的）

1. **字高口径差 2×描边。** 模板写 0.045H，像素实测 0.0516H，差值 0.0068 ≈ 7px 描边 ×2。
   模板的字高指**字**，成片的字高是**字 + 描边**。谁拿模板的数去验成片，都会判"超了"。
   验的时候要按 `模板字高 + 2×描边宽` 比，或者干脆只比区间不比值。
2. **推镜切有个洞。** 原来只在段长 > 1.6×目标中位时才拆，于是 4.8–5.4s 的口播段不拆，
   镜头中位顶到 5.1s、超模板上限 4.8s（实测：proj2 第一版）。阈值改 1.25× 后 4 镜都 2.6s。
3. **白像素裁判在白字压亮底时直接失效。** 书架口播那条是白墙背景，白像素判据报"没有字幕"。
   改判**横向边缘能量**（字是硬边、背景是软的，亮底也压不住）后，两批素材都量到 0.859 / 0.045。
   同一套判据在 C 族的角标上又栽了一次：亮水泥地面在顶部就有 1–2% 亮像素，和 1.4% 小字量级重叠，
   按亮度判会误判到 24.7%H 和 4.8%H 两处。换成判"**同一镜头内两帧像素差 <5**"（叠加层是画上去的，不动）才准。

## 六、没做的

- **人眼混洗**：把复刻帧和参考帧混在一起，让人分不出哪个是哪个——这需要 Jerry 或第二个模型的眼睛，机器做不了。
- **B / D / E 三族没做换素材测试**：今天只验了 A 和 C。B（宋体 + 底部留白 24%）与 E（卡片 + 分屏）的 token 结构不一样，得各跑一轮。
- **音效**没实现，所以 C 族永远是 7/8。

Jerry 2026-11-08 11:59 的判词是「差距很大」，拆成五条：形式要像、缺音效、人物抠像字放背后、缺代码画的 B-roll、大字出现的时机不对。

## 三、这一轮真正学到的东西

### 1. 「字高 0.0906H」是我们量错的，不是片做错的

`measure_pack` 原来取"方差最大的那一行当字幕带"，然后往外扩到 9%H 的上限。问题是花字、章节卡比字幕更亮更跳，往外扩会一路吃到上方那些层，最后把**花字 + 字幕**合成一条 9%H 的带。

参考片和成片**同时**报出 0.0906H——两支完全不同的片子撞到同一个上限，这本身就是判据坏了的信号，而不是它们一起做错了。

改两处：① 取**最靠下**的那段（字幕永远是画面里最低的一层文字）；② 只往外扩 2 行。改完参考片 0.0375、成片 0.0344，都在带内。

### 2. 音效密度这一项，凡带人声的片子都量不准

黑盒测音效靠"能量突跳"，人声每个词都是一次突跳。参考片 126 秒被测成 0.0（它其实有音效），成片手打 9 处（6.8/分，模板 4.0–8.5）被测成 12.9。

**同一个数字在两个方向上错，就说明它不是尺子。** 现在这一项改成「仅供参考」，不参与判定。要判它只有一条路：拿混音用的 `cues.json` 数它自己——那是设计值，不是测量值，所以只能自己对自己。

### 3. 整屏信息卡必须铺底，且字幕要让位

第一版的章节卡是"浮在画面上的米白卡片"，占屏 60–70%，四周露出实拍和字幕的下半截——同一屏出现两套字，读的人当场就乱。

参考片那张图谱卡出现时，底下的实拍已经看不见了。所以：`spec.backdrop` 给整幅铺一个深色底；卡片窗口内的字幕**整条不画**（`_fullscreen` 过滤）。

### 4. 抠像的羽化边会在亮字上"长白毛"

`alphamerge` 直接吃软边遮罩，人压在明黄大字上时，那圈半透明的边把背后的黄色透上来，看着像人物轮廓自己发亮。

修法：遮罩先二值化（`lut=y='if(gt(val,140),255,0)'`，阈值略高于中值 = 顺手把边往里收一点）。1080p 下硬边看不出来，羽化边一眼就看得见。

顺带确认：裁切放大后那圈亮边是**素材自带的轮廓光**（偏黄、1–2% 人物宽），不是合成缺陷。这是"看图判读"和"量像素"能给出的两种不同结论，两个都得看。

## 四、还没追平的

- **章节卡的内容**：形状照住了（5 列 / 整屏 / 左轴 / 列头），但参考片是"一堂基本功清单 5.0"那种有体系的图，我们的是 17 个选材 checklist。形式像，内容不是一回事。
- **片头身份卡**（Truman / 一堂CEO / 以太创服合伙人 四行左对齐、无底衬）没做。
- **花字的入场动效**：参考片有轻微过冲，我们只有 `entry: pop` 的位置跳变，没有时间曲线。
- **B / D / E 三族**仍然没做换素材测试。
- **人眼混洗**没做——这是唯一能证明"像不像"的裁判，机器替不了。

## 补记 · 音效为什么之前"打了等于没打"

`mix_sfx.py` 有一道护栏：混完不许越过 -1 dBFS，越了就把**音效床整体压小**（人声一动不动）。这道护栏本身是对的——主轨已经被 loudnorm 顶到 -0.99 dBFS，保护人声优先。

问题是它的位置错了。音效是在**归一之后**才混进去的，于是每一处音效都在往天花板上顶，护栏只能把整张音效床压掉。实测 9 处里 **6 处带内提升 0.0 dB**——混了，但等于没混。

改法：混完再归一一次（`audio_final.wav`）。让响度归一器一次性去解决"人声和音效的相对关系"，而不是先钉死人声、再逼音效让路。改完 whoosh 三处带内提升 6.3 / 12.3 / 46.7 dB，峰值回到 -0.98 dBFS（不越限）。

**留下来的问题**：pop/tick 这类 50–100ms 的短促音，落在连续人声里只涨 1–2 dB。这不是音量没给够（已经给到 -3/-4 dB），是**结构性的**：它们和人声在同一个时间窗里竞争。真实剪辑师的做法不是加音量，是给 90ms 的 duck（人声让 4–5 dB）或把落点挪到最近的换气口。这一步还没做。

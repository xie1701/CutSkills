# 盲测怎么做才算数

盲测是 B 段唯一的外部裁判。做错的盲测比不做更糟：它会给你一个「读者都说好」的错觉。

## 一、什么时候跑

| 时机 | 必要性 | 说明 |
|---|---|---|
| B 段确认前 | **必须** | 稿子定版之前跑一次。这时改一句话只花一分钟，出了片再改要重渲 |
| 改完再跑一次 | **必须** | 盲测的价值一半在第二次：被指出的段消失了没有？没消失就是没改到点子上 |
| 发布前 | 可选 | 如果加了封面、改了开场，值得看一次开场那 5 秒的反馈 |
| 每次改一个字 | 不必 | 盲测测的是「说清没有」，不是逐字校对 |

## 二、把包发给谁

**一次至少三种身份**，因为三种人卡的地方不一样：

| 身份 | 他能看见什么 | 典型指认 |
|---|---|---|
| 普通观众（陌生人） | 只看你说了什么，没有背景 | 「这个反问我没听过哪个客户这么说」——证据是编的 |
| 目标客户（业主 / 采购） | 关心「这对我有什么用」 | 「讲了半天没说贵多少」——他真正要的信息没给 |
| 同行（工长 / 设计师） | 关心「你说的对不对」 | 「耐擦洗、返工率一个字没提」——该有的专业细节缺了 |

同一个人只给一种身份。**不许在提示里透露作者是同行、是甲方，也不许说「这是我们做的片子」**——那会让对方开始照顾你的面子。

## 三、同源偏差：为什么不能只让一个模型读

同一个模型家族会用同一套审美、同一套宽容度读你的稿子。它读出来的问题，往往正是你写的时候没意识到的地方；它读不出问题的地方，也常常正是你们共同盲的地方。

七条缓解，从便宜到贵：

1. **换家族**：另一个厂商的模型。最便宜的一次去偏（同一个钱包，不同的训练口味）。
2. **换档位**：同一家的小模型反而更接近「滑过去看的观众」，大模型更像「认真挑的同行」。两个都用，别只用一个。
3. **换身份**：同样的稿子，给三种人设各读一遍（见上表）。身份差异比模型差异更能暴露问题。
4. **换模态**：把稿子用 TTS 念一遍、让人**听**。文字能跳读，声音不能——听的时候「听不懂」会比读的时候更早暴露。
5. **换问题形式**：不问「你觉得怎么样」（只会得到客气话），问封闭题：哪一段最弱（必须给序号）／你会不会继续看（会·不会·说不清）／一句话复述它想让你信什么。
6. **换时间**：自己隔 24 小时再读一遍，或者让同一个模型在**没有上文的新会话**里读。上下文就是最隐蔽的偏袒。
7. **接真实数据**：完播率、前 3 秒留存、评论里第一句质疑是什么。这是唯一不带偏差的裁判，也是最慢的（v2 再回流）。

**成本最低的一次去偏**：第 1 条 + 第 3 条一起用——两个家族、三种身份，跑一轮不到十分钟。

## 四、怎么判读

| 现象 | 结论 | 动作 |
|---|---|---|
| **≥2 位裁判点到同一段** | 高信号，基本可以当成真的 | 去 `gap.md` 看它属于「缺证据」还是「缺说理」，然后改 |
| 只有 1 位点到 | 可能是个人偏好 | 记下来，不改；如果同一处反复被单人点到，就升级 |
| 所有人点的地方都不一样 | 信息密度不均匀，每段都缺一点 | 别逐段补，回头砍段或换结构 |
| 裁判读出的主张 ≠ 你承诺的 | 承诺没被说清，通常是开场和收束的问题 | 先改开场/收束，不要加素材 |
| 证据 0–1 条 | 只有主张 | 论点缺证据，`gap.md` 会列 |

**别用聚合分数定去留。** 「三位裁判打 7.5 分」这种数字没有意义——它会把「同一处缺口被两个人独立指出」这件最重要的事平均掉。看段落，不看分数。

## 五、机器能查的 vs 只有裁判能查的

这一条决定了这套流程的分工，别互相替代：

| 问题 | 谁查 | 例子（柒造这条片子的真实结果） |
|---|---|---|
| 有没有论点、论点有没有证据 | 机器（`check_edl`） | 「论点 4 只有主张没有证据」 |
| 证据段里有没有数字和名字 | 机器（`check_edl` 的泛述词检查） | 「#9 有『相当一部分』但没有任何数字或具体名字」 |
| 这句话是不是编的、转述有没有交代谁说的 | **只有裁判** | 「#1 这个反问我没听过哪个真实客户这么说」「#4 是谁说的没交代」 |
| 主语有没有跳、听不听得懂 | **只有裁判** | 「#5 我不知道『他』指谁」 |
| 专业内容够不够硬 | **只有裁判（同行）** | 「耐擦洗、附着力、色差、返工率一个都没提」 |
| 读者想要的判断依据给了没有 | **只有裁判（目标客户）** | 「界面没给贵多少、差在哪个性能」 |

机器报的三条（#2 #3 #8 #9 泛述）和裁判点的五段（#8 #9 #10 #11 #13）**在 #8 #9 上重合**——这就是两套判断互相验证的样子。重合的地方先改，不重合的地方各归各的类。

## 六、留痕

跑完记一行，不然下一轮不知道改过什么：

```bash
log_decision.py --project <项目> \
  --said "盲测：3 位裁判，#8#9#10#11#13 被 ≥2 人指认说不信" \
  --did "改 #9 补一个具体项目名；#11 补进口与国产的价差区间"
```

`blind-report.md` 每轮保留，不要覆盖掉旧结论——「上一次被指出的段这一次还出现吗」是这套机制唯一的成绩单。

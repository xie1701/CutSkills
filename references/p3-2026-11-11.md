# P3 · 代码画面四原语 + 石灰基三幕（2026-11-11）

准绳仍是 `references/plan-v3-2026-11-11.md` 的维度三。这一份只记 P3 做成了什么、量到了什么、还差什么。

## 一、四原语（`scripts/gen_scene.py`）

以前是「一部片一个函数」：`scene_phase` / `scene_pour` / `scene_measure` 各写各的几何，
谁也用不了谁。现在先有四个可组合的东西，场景才是它们的组合：

| 原语 | 一句话 | 落在哪 |
|---|---|---|
| `Subject` | **谁在变**：一块几何体（归一化角点），`id` 从第一幕活到最后一幕 | `Subject.px(W,H,cam,k)` 负责投影 |
| `State` | **变成什么**：填充色 / `grain` 粗糙度 / `gloss` 光泽 / `label` | `draw_subject()` |
| `Transition` | **怎么变**：原地变（morph）／浇上去（pour）／干（dry） | 场景里按 `marks` 算混合系数 |
| `Camera` | **镜头**：一条连续曲线（`zoom` / `dy` 两端 + ease），不切不回正 | `Camera.at(k)` |

为什么镜头只给一条曲线：20 支参考片量出来的是「一次推近只持续一句」。连续场景每幕都 ≥8 秒，
一句话就是一条曲线的事；切成三五段反而像演习。

**承接通因此是结构性的**：`Subject.id` 不变 + `Camera` 连续，于是「像不像 PPT 翻页」
这个问题从「靠转场救」变成「本来就不会发生」。

## 二、石灰基三幕（`scene_lime`，B 轴第一支 demo）

```
一·出身   石灰石 ──煅烧──► 生石灰
二·变化   生石灰 ──消解·熟化──► 膏体
三·落点   膏体 ──上墙──► 成品
```

- 同一块 `Subject("lime-slab")`，镜头 1.0 → 1.17 连续推近、纵向漂 0.03。
- 节拍靠 `--marks` 从 ASR 字级时间戳算（默认 0.30 / 0.62）。
- **画的是示意，不是工序**：真实工序是石灰石→煅烧→消解→熟化→施工；温度、时长、设备一律不画，
  画面右下角常驻「示意」两字。

实测（12s / 1080×1920 / 30fps）：

| 指标 | 值 |
|---|---|
| `--probe` 收尾 | 结尾亮像素 30.2% / 峰值 30.5% → 🟢 收尾没空 |
| luma 剖面 | 57.7 → 56.4 → 67.8 → 81.2 → 96.0 → 81.5（越演越亮，成品最亮） |
| 帧差（8fps 采样） | 中位 1.02 / 最小 0.11 / 最大 2.87 |
| 最长静止 | **0.88s**（判据：≥2s 才算冻结） |

第一版被自己的复核打回：0.5s 与 4.0s 两帧几乎一模一样——因为那一幕除了颗粒微微抖动，
画面没有任何一直在动的东西。修法是**每一幕各有一件持续运动**（一幕石屑下落、二幕煅烧热粒上升、
三幕后段抹痕逐刀覆盖），不是加转场。

## 三、还差什么

1. **没接进时间轴**。`render_hf.py` 认 `template: scene` + `props.scene: lime`，但 B 轴准入要求
   这一格有 `audio`（`check_timeline` 会拦），demo 还缺一段 ≥8 秒的旁白。现在这支是静音样片。
2. `phase` / `pour` / `measure` **没改成四原语的组合**。它们是被眼睛调过两三轮的，硬重写等于把
   已经对的东西推倒；四原语先由 `lime` 当参考实现，等第四支场景再抽。
3. `fx` 里声明的 `morph_carry` / `sweep` / `particles` 仍是「声明先行」——`check_packs.py`
   已经会把它们标出来（警告不判红），但片子里这几样效果还不会发生。
4. 三幕的**时长比例**没有标定：一条 12 秒的示意线，出身/变化/落点该按几比几分配，现在按 0.30/0.62
   拍的。等有成片旁白之后按词重算。

## 2. 标定结果（20 支参考片 + 我们 3 支）

不只用我们那三支。语料：`/Users/jerry/Downloads/参考包装视频` 下 20 支成片（合计 67 分钟，576×1024 到 1280×720，23.97–30.06 fps，含口播、访谈、家居、教程、混剪五种形态），加我们自己三支成片。全部用我们现成的 `skeleton.detect_cuts()`（自适应 MAD 阈值，不是 ffmpeg scene 分数）量。

| 指标 | 20 支参考片 min / p25 / **p50** / p75 / max | 我们三支 | 结论 |
| --- | --- | --- | --- |
| 画面变化 CV | 0.417 / 0.592 / **0.667** / 0.828 / 1.226 | 0.747 / 0.777 / 0.821 | 阈值定 **≥0.42**（不是外面那套 0.25，太松）；p50 0.67 是「舒服」 |
| 死静占比 | 0.000 / 0.016 / **0.084** / 0.179 / 0.424 | 0.000 / 0.000 / 0.027 | **作废**。8/20 支成熟片接近 0，没有区分力 |
| 画面变化中位 | 1.08 / 1.99 / **2.19** / 2.69 / 6.96 | 1.17 / 1.27 / 1.83 | 观众的「换画面」锚点是 **2.2s**，不是 2.8s |
| 冻结 ≥2s 的片数 | **7/20** | 0/3 | 不能全片判死。只在**口播段**（有人脸、有人声）判，空镜/静帧/片尾豁免 |
| 平均亮度 | 0.145 / 0.300 / **0.391** / 0.512 / 0.880 | 0.364 / 0.405 / 0.472 | 外面那套「Y 30–60」等于 0.12–0.235，会把 20 支里 19 支判死。**降级为诊断** |
| 最暗 1s 窗口 | 0.001 / 0.028 / **0.090** / 0.178 / 0.799 | 0.209 / 0.266 / 0.334 | 同上，只报「连续 1s 全黑」这种真事故（<0.02） |
| 音轨比视频长 | **13/20**（最大 +0.155s） | +0.067 | 判据单向：`0 ≤ a_dur − v_dur ≤ 0.2`，**不许音轨更短** |
| color tag | 18/20 有、2/20 缺 | 3/3 齐 | 我们保留「必须 bt709」是**自家规矩**，不是行业事实——写清楚 |
| 流起点差 | 20/20 都是 0.000 | 0.000 | 判据保留（≤ max(0.1, 2/fps)），三行代码的保险 |

三条最反直觉的发现：

1. **我们的 CV 比参考片中位还高**（0.78 vs 0.67）。所以「像 PPT」在我们这里不成立在**节奏**上，问题只在**承接通**上——两张卡换得太干净。这修正了我上一轮的归因。
2. **「口播镜头中位 4.89s」和「画面变化中位 1.27s」在量两个东西**。前者是素材里的机位切换，后者是观众感知的画面事件。参考片这两个数值几乎相等（2.83 / 2.19），**我们差 4 倍**——因为它靠跳剪+推近，我们靠叠卡。结论：不是回去重切镜头，是**给 A-roll 加跳切推近**（WP7）。
3. **7/20 支成熟片里有 ≥2s 的冻结**（多半是照片/空镜持有）。外来那条「冻结=坏片」如果照搬，会误杀三分之一的行业成品。

## 3. 工作包

四批、14 个包。每包给：改哪、判据、验收、成本、风险。

### 批一 · 机判补硬（0.5–1 天，不碰链路）

**WP1 `verify_film.py` 加 5 条**
- 冻结：`freezedetect=n=0.003:d=2`，只在「有口播声且画面是 clip」的时间窗里算；`image`/`gen`/`silence`/片尾 2s 豁免。级别 🟡。
- color tag 三标：`bt709/bt709/bt709`，缺一 🟡。
- 流起点差：`|v_start − a_start| ≤ max(0.1, 2/fps)`，超 🔴。
- 音轨等长：`0 ≤ a_dur − v_dur ≤ 0.2`，负值 🔴。
- 最暗 1s：连续 1s 均值 < 0.02 且该段有声 → 🟡（无声段不管）。
- 验收：naming-01 复跑，报告多出这 5 行读数。

**WP2 字幕展示单位（`subs.py`）**
- `display_units(text)`：中文/全角 = 1，英文数字 = 1/3。行宽上限 `≤10 单位` 且像素 `≤0.92W`。
- 现在 `len(txt)` 会把 `FESTOOL RO 150 FEQ` 当 18 字砍掉；改后同宽度能装下。
- 验收：造 3 条混合中英字幕，检查不再被砍、也不出画。

**WP3 字幕半开帧窗 + 零重叠硬判（`subs.py` / `check_subs.py`）**
- 输出改帧整数 `[startFrame, endFrame)`，相邻可相接、不许重叠（含淡出尾）。
- 重叠 = 🔴，不给 `--force` 越过（这是画面上必然看得见的错）。
- 验收：构造一条 1 帧重叠，必须红。

**WP4 `review_sheet.py`（目判工具，全新）**
```
python3 scripts/review_sheet.py <proj> --sheet 16          # 全片 16 帧总览
python3 scripts/review_sheet.py <proj> --stills 12.3 30.5  # 原尺寸单帧
python3 scripts/review_sheet.py <proj> --motion 22.1 22.6  # 转场区间 12 帧
python3 scripts/review_sheet.py <proj> --variants mute,subs-only
```
- 产物 `proj/review/`：`sheet.jpg` + `manifest.json` + 两个变体片（静音版、只留字幕版）。
- 这是本轮我最想要的东西：过去两轮你说「先逐帧审核」，我只能靠自己猜时刻，找不全。
- 成本 0.5 天（拼图/抽帧都是 ffmpeg 一行，变体片是 `-an` 与「只留字幕层」两条 filter）。

### 批二 · 编排与镜头（1.5–2 天，改叙事）

**WP5 三层节奏（`styles/*.yaml` + `timeline.py`）**
- `rhythm: {micro: [0.35, 0.9], scene: [1.8, 3.5]}`。
- `gen` 模板内部支持 `micro`：一张卡在场 3 秒，内部必须有 2–4 次小变化（数字滚动、行逐条进、色块位移）。
- 判据：任一 `gen`/卡片段内，事件间隔 > 1.2s → 🟡。
- 验收：naming-01 三张卡各加 2 处微事件，抽帧能看出卡内变了。

**WP6 边距按介质分档（`timeline.py`）**
- 词间硬切：`PAD_CUT = (0.03, 0.05)`（不动）。
- 换介质（talking→broll/image/gen）：`PAD_MEDIA = (0.50, 0.60)`。
- 「在手伸到镜头前停」写进 `references/audio-first.md` 作为选点规则。
- 风险：全片会变长 1.5–3 秒，`brief.py` 要给提示。

**WP7 跳切推近（`timeline.py` + `render_hf.py`）**
- 素材是长镜头时，同一句内每 2.0–2.8s 切一刀，每刀换一个推近倍率（1.00 / 1.06 / 1.12），一句内不重复。
- 一次推近只持续一句，句子换就回 1.00。
- 判据：口播镜头中位进 **2.4–3.2s**；推近段内 `scale` 单调、无回弹。
- 风险：`cover_fg` 抠像层是全帧裁切，推近后 `crop_h` 要重算（否则字幕带被人挡住，正是上次修过的坑）。必须先改 `cover_fg` 支持 `zoom`。
- 预期：这条直接把 naming-01 那条红🔴 变成绿。

**WP8 `role` 六分类 + 数字纪律（`timeline.py` / `check_timeline.py`）**
- `role ∈ {evidence, explanation, calibration, organization, action, consequence}`，`gen` 格必填。
- 数字类 gen（`number`/`chart`/`compare`）必须给 `source`（出处）或 `approx: true`（画面自动加「示意」角标）。
- 判据：`gen` 缺 `role` → 🟡；数字卡既无 `source` 又无 `approx` → 🔴。

### 批三 · 卡种与承接通（2–2.5 天）

**WP9 卡种 10 → 18（本地那份可整段移植）**
- 移植 8 张：`stat-proof`（巨号数字+脚注）、`ring-metric`（指标环）、`rank-bars`（排名条）、`versus-card`（对撞）、`checklist`（清单）、`step-timeline`（步骤轴）、`entity-chips`（实体芯片）、`quote-lockup`（金句定格）。
- 同时移植它的**高度估算表**（每类卡的近似宽高，「宁可高估」），接到我们的 `top_h` 计算上——先量高度，再选带，长列表就不会压字幕。
- 判据：每张新卡在 1080×1920 上跑一遍 `--stills`，宽高不越 0.92W / 不压字幕带。
- 风险：它的卡是「深色卡 + 强调色」世界，我们的 `talking-head-v1` 是暖色实拍。要先做一层 `theme` 变量（背景/文字/强调三色），否则拼在一起像两套片子。

**WP10 承接通（结构判据优先，像素探针 v2）**
- **v1（设计期，当天可上）**：`check_timeline.py` 判「相邻两个换介质的格，必须共享一个视觉元素」——同 asset 的延续、同 template 的 morph、同色卡背景、或大字延续。共享不了就必须显式写 `hard_cut: "理由"`，才算过。
- **v2（选做，需 1 天 spike）**：在成片上用 12×20 网格块匹配算位移/缩放，判 carried/anchored/bare。
- **止损线**：v2 的 spike 如果误判率 > 20%（拿 20 支参考片当阴性样本），就不上，只留 v1。理由：外面那套探针的误杀风险写在它自己的盲区表里，我们不能不验就搬。
- 判据：v1 的 `bare` 边界数 = 0；v2 若上，carry ≥ 0.5。

**WP11 节奏 CV（`verify_film.py`）**
- 由 `detect_cuts` 出来的切点算镜头长 CV，阈值 **≥0.42**（本库标定的下限）。
- 与「口播镜头中位」并列显示，两个数字分别代表「素材切换」与「感知变化」。

### 批四 · 声音与收口（1–1.5 天）

**WP12 `audio_diag.py`（新）**
- 量三件事：3kHz 以上能量占比（低于 8% → 麦克风被遮/糊）、频谱倾斜（低频占比 > 0.5 → 闷）、削波与直流偏移。
- 输出「糊/吵/闷/正常」四档 + 一句建议（EQ 方向 / 降噪 / 保持）。
- 这是给我们工地素材的第一份体检，以前只有 loudnorm 硬顶。

**WP13 垫乐「静则抬」（`render_hf.mix_bgm()`）**
- 现有：有人声就 duck。
- 新增：连续 0.4s 无人声 → 垫乐 +3 dB，起于尾音后 0.15s，0.5s 缓升；人声回来 0.12s 内落回。
- 判据：B-roll 段垫乐与人声段的电平差 ≥ 2.5 dB。

**WP14 音效上限（`check_sfx.py`）**
- 现有判据只有下限（「高出基线 3dB 才算听得见」），会逼着音效越来越响。
- 新增上限：音效峰值不得高于口播峰值 − 6 dB。
- 同时把 `SFX_MAP` 里偏具象的族（pop=咔哒、whoosh=风）换成更柔的（低频 swell、纸面摩擦），只在 `behind/大字` 与整屏换镜时用。

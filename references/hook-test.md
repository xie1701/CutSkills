# 前 3 秒 A/B：怎么跑，怎么算过

## 为什么放在最前面

整条片 79 秒，改一次要 1 分半渲 + 1 分钟验；而观众决定要不要继续看，是前 3 秒决定的。
所以「钩子」不能等整条出来再看——那时候它已经被后面的结构绑死了。

这不是「多做几个版本」，是广告投放里的 creative testing：同一份 brief 出几个钩子，
用小成本测，赢的那个才值得做长版。

## 三个候选是什么

`hooks.py` 出的是三种**不同的开场策略**，不是同一个策略的三次尝试：

| 候选 | 策略 | 素材从哪来 | 什么时候选它 |
|---|---|---|---|
| **A 结论前置** | 第一句就把主张说出来 | plan 里 `role: claim` 的第一段 | 主张本身够反常识，不需要预热 |
| **B 现场切入** | 先给最硬的画面，人后出 | 索引里 `must-use` 且带动作的 B-roll | 现场比话好看；工地、制作过程类 |
| **C 反差提问** | 把观众现在的想法打在画面上 | 代码生成（`keyword` 模板） | 库里没有能打的画面，或需要一句直击的话 |

C 并不是「没素材时的将就」：它念的是 `brief.json` 里 `audience_present_state`——
**观众现在信的那句**，然后加一个问号。写反过一次（把「要他怎么变」截断成六个字打上去，
读起来像被刀切的），记住：钩子念的是他的想法，不是我们的要求。

## 怎么测

```
python3 scripts/hooks.py --project <项目> --render
```

产物：`<项目>/hooks/A-结论前置.mp4` 这类 3 秒短片，各 1–3 MB。

测法按成本从低到高，**最低那档也必须做**：

1. **自己看**（10 秒，最低档）。三个连着放两遍，问自己「哪个让我想接着看」。
   只记结论不记理由没用——理由才是下次的判断依据。
2. **拉 2–3 个人看**（3 分钟）。放完问一句「你会继续看哪个」，**不给任何背景**。
   给背景就污染了：观众点开视频时没有背景。
3. **小额投放**（有钱有账号时）。同一时间窗口投同一个预算，看 3 秒完播率。

## 怎么算过

- **2/3 以上的人选同一个** → 过，按那个走：`hooks.py --choose A --note "两个人说 A 更抓人"`。
- 三个人各选一个 → **没过**。说明三个候选都没有钩子力，问题在钩子本身，
  不在选哪个；这时该回第 1 层改 `audience_present_state`（可能你猜错了观众现在信什么）。
- 一个人都没选出来 → 没过，同上。

## 留痕

`--choose` 会把定案写进 `decisions.md`（一行，附录用原话）。良率卡读 `hooks.json`
的 `chosen` 与 `passed` 字段：**没做就写「没做」，不许默认算过**。

## 已知的坑

- 三个候选都是 3 秒短片，**渲它们也要切素材**，冷缓存下 3 条约 2 分钟。
  同一批素材第二次跑会命中段级缓存，快很多。
- 候选 C 是全屏文字，没有声音。如果它赢了，接整条时要处理「第一句什么时候进来」——
  现在接法是第一格直接是它，第二格才是人说话。
- 别拿这三个候选去比「哪条整片更好」。它们只回答一个问题：**要不要看下去**。

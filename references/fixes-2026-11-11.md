# 审查后的修复 · 2026-11-11

## 一、真红治好了：口播镜头中位 4.89s → 2.45s

HyperFrames 链一直没有「拆镜」这一步，所以口播一格 4.9 秒就是一镜到底。
补上**跳切推近**（jump cut + punch-in）：

- 一个句内每 ~2.4 秒硬切一次，切点吸附到**字界**（`chars` 的起点，±0.35s 内）；
- 倍率先 1.0 → 1.14（骨架不同：S1/S4 1.16、S3 1.10），**外加 ±2% 横向位移**——
  纯中心放大读作「缓慢推镜头」，加位移才读作「换了一镜」；
- 声音一点没断，时间轴一格都没动（`timeline.json` 不变），所以切点、字幕、卡片全不受影响；
- B-roll 也拆（参考片画面变化中位 2.19s，不分口播还是空镜）。代码画的连续场景**不拆**——
  那是「一件事在变」，中间切一刀正好打断它。

切片留 1.2 倍**富余**（`--overscan`）：推近是 CSS 放大，源片就 1080×1920 的话放大等于拽糊
（视觉复核原话「面部出现数字模糊」）。现在切出来是 1296×2304，放大到 1.2 之前都有真像素。

实测（`qizao-naming-01`，41.5s）：

| 剪辑点（全部镜头） | — | **16 个 · 中位 2.47s 🟢**（S2 档 2.2–2.7） |
| 验收 | 🟢25 🟡1 🔴1 | **🟢30 🟡0 🔴0** |

## 二、双语双行：从「假称」变成能用

- 渲染器现在读 `subs-en.json`（`{"1": "No grand theories, but..."}`，键是字幕序号），
  给每条 cue 挂 `en`；`subtitle_system: bilingual` 才渲染第二行（`<i class="en">`）。
- 没有 `subs-en.json` 就还是单行，并且**明说**（stderr + `check_packs` 判黄）——
  不再出现「配置写着双语、画面只有一行」。
- 给 `qizao-naming-01` 写了 18 条英文，实测 HTML 里 **18 个 `cap-bi` 块 / 18 行英文**，
  字体也对（宋体 = P2-paper）。

## 三、B 轴：石灰基三幕接进真时间轴了

不再是静音样片。新项目 `qizao-lime-baxis`（13.94s）：`template: scene` + `props.scene: lime`，
声音取真旁白 `熊工口播3` 675.84–689.78（「它要去进行水化……白云石煅烧，或者说是石灰石煅烧，
就有一个温度的讲究」），`marks` 按词时间算成 0.331 / 0.581。

- 渲染：13.9s · 5.8 MB · 响度 −14.25 LUFS / −1.81 dBTP · 垫乐 CC0 自动挑；
- 验收 **🟢23 🟡0 🔴0**：代码画面 #1 的声音 −16 dB 🟢、不是静图（最长静止 0.67s）🟢、
  场景内微事件间隔 2.30s 🟢。

顺带修掉三个挡路的东西：
1. `render_hf` 的「一格画面都没造出来」判据漏了 `scenes` —— 纯 B 轴片（整支都是场景）直接报错出不来；
2. `scene` 模板上限 9s 与 B 轴准入 ≥8s 自相矛盾，放到 16s；
3. `check_timeline` 的 `micro` 只认 dict，写字符串直接 `AttributeError` 崩掉（报错比错误难懂）。

**B 轴的节奏不走 band。** 它本来就不该有剪辑点——拿「剪辑点中位 2.7–3.4s」判一支连续场景，
等于要求「一块石灰基的一生」每 3 秒切一刀。改成判**场景内微事件间隔**（≤2.5s，与
`check_timeline.MICRO_GAP_MAX_SCENE` 同一个数）。

## 补记（11-11 03:1x）· 双语双行与纸感字幕

**两个真 bug，都是「说的和做的不一致」这一类：**

1. **双语双行从来没上过屏。** `.cap` 同时带 `.clip`，`.clip` 是 `inset:0; height:100%`，
   字幕框被撑成整屏高。单行时行盒在框顶看不出问题；双语是 `column + align-items:center`，
   整块被垂直居中到 y=2254（画面高 1920）——HTML 里 18 个 `<i class="en">` 一条都没出现过。
   修法：`.cap { bottom:auto; height:auto; }`（`.kw` 同理）。
2. **纸感包的字幕字色。** 深墨字压在暗画面上：字幕带 p98 152 / 字 30。三条路里
   纸底（被同一个 100% 高度推到画面外）、暗晕（复杂背景像脏斑）都不行，
   最后用 `subtitle.light_text`：奶白字 + `paint-order:stroke fill` 2px 描边 + 深影；
   英文行跟着换色；浅底代码画面上重叠的 cue 换深墨字（`cap-ink`，按 gen 时间跨度判）。
3. **传染性统计 bug**：P3 渲一次把 `subs.json` 的 `chars_per_s` 写成 0，同项目 P1 成片验收
   就被判「字幕密度 26 条/分钟、期望 0」。统计改成与包装无关 + verify 侧就地重算。

**还没解决的两处（交给人眼）**：字幕压在第 16/17/18/20 格代码画面上仍偏弱；
大字底边到字幕顶边只剩约 60px，视觉上有顶到一起的嫌疑。

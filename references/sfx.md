# 音效怎么用

音效是包装里最晚补、也最容易补错的一层。这一页只讲三件事：**素材从哪来、cues 从哪来、给多少**。

相机和素材库里没有音效可用——参考片里的音效是剪辑师从商业音效库一层层挑的，那些库不能下（依赖只装一次、不许重复下载）。
所以这一层改成**代码合成**：`scripts/gen_sfx.py` 算一次落盘，之后按包装置换音效只读文件，不再重算。

## 一、四个音，各管一件事

| 名字 | 时长 | 主能量 | 用在 | 什么时候不给 |
|---|---|---|---|---|
| `whoosh` | 0.33s | 1.9k → 4.4kHz 上扫 | 硬切点、镜内推镜切、场景切换 | 连续推镜的中间不要给，会变成"呼呼"底噪 |
| `impact` | 0.42s | 849 → 193Hz 下扫 | 段落转折、论点落地、片尾收 | 一支片别超过 2 次，多了就成鼓点 |
| `pop` | 0.10s | 270 → 118Hz + 3.6k 咔哒 | 大字/花字入场、数字弹出 | 字幕带常规换行不给（那是文字流，不是事件） |
| `tick` | 0.05s | 4.3k → 3.5k | 列表逐条出现、数字计数 | 同屏连给两记以上就成打字机 |

全部是短促的机械音：噪声带通 + 包络 +（pop/impact 的）低频滑音，**没有音高旋律**，也没有混响尾——混响会让它们听起来像"素材库的罐头"。
四个音的**峰值统一 -6 dBFS**、48k / 单声道 / 16bit，素材不会因为峰值不一而需要逐条拉增益。

落盘位置：`${CUTSKILLS_HOME:-~/.cutskills}/assets/sfx/`，**不进仓库**。

```bash
scripts/gen_sfx.py                        # 全部；已存在就跳过（幂等）
scripts/gen_sfx.py --name tick --force    # 重做单个
```

## 二、cues 从哪来

cues 是一张时间表：`[{"t": 3.2, "name": "whoosh", "gain_db": -6}, ...]`，`t` 单位秒、对齐成片时间轴。

**切点不要手拍，用 ffmpeg 的 scene 检测**（阈值 0.12 在这批竖屏口播上够用，0.30 会漏掉大部分推镜切）：

```bash
ffmpeg -v info -i out/film.mp4 -vf "scale=320:-2,select='gt(scene,0.12)',showinfo" \
       -an -f null - 2>&1 | grep -o "pts_time:[0-9.]*"
```

**大字/列表/转折的时间不要猜，从已有的产线文件里取**：

- `out/subs.json`、`out/shots.json` —— 字幕条和镜头边界
- `render-report.md` 的「字卡」段 —— 字卡起止（例如 `65.27–70.87s`）
- `edl.json` 的段起点 —— 段落转折

三个都拿不到才退回到 scene 列表里挑"跨段"的那几个。

## 三、给多少：音效密度必须和切点解耦

`references/packaging-families.md` 铁律三：**音效是标点，不是鼓点。** 同一批参考片里两端都出现过：

- `质感剪辑3法宝`：95 个切点，只有 13 个切点带 5–8k 瞬态（低于随机基线 18.3/95）——切点全靠画面成立，只在整屏字卡换段处给一记 +25.4dB。
- `把所有权限交给AI`：17 个切点里 13 个带瞬态，是最密的一端。
- 中间地带：66–72%（12/18、13/17、13/18）。

所以 `sfx_density_per_min: [2.0, 6.3]`（C 族）**不是目标值，是上限**。一支 79 秒的口播片，按 8.5 处/分封顶也就是 11 处；按 C 族落在 3–8 处。
落到操作上：

1. 先只给**段落转折**（每 15–25 秒一记 `impact`）。这一步做完，片子已经有骨架了。
2. 再给**字卡/大字入场**（`pop`），一支片 2–4 记。
3. 最后才给**切点**（`whoosh`），而且只给"景别/空间变了"的切，同类镜头内部的推镜切不给。
4. 每加一处问一句：这里**没有**音效观众会不会少知道点什么？答不出来就删。

数密度时按成片时长算（`处数 / 时长(分)`），别按切点数算——`十亿女总裁` 实测 7.9 处/分，摊到 173 个切点里只覆盖 1/17。
反过来说：**切得越密，越该少给音效**。切点密度高的片子，画面自己就够了。

## 四、给多响：增益是相对素材的 -6 dBFS 峰值算的

`gain_db` 是叠在素材峰值上的，所以 `-6dB` 的 cue = 混后峰值落在 -12 dBFS。**别照搬手感，照人声轨算**：

- 人声轨是 loudnorm 出来的，样本峰值本来就在 **-0.9 ~ -1.0 dBFS**、语音 RMS 约 -12 dBFS。
- `whoosh -14dB` → 素材峰值 -20dBFS、RMS 约 -35dBFS，比人声低 23dB。**实测在一支 -14 LUFS 的口播片上，这种增益的 whoosh 混进去，100ms 窗口 RMS 只涨 0.0 dB——等于没给。**
- 可用的区间：

| 音效 | 建议 gain_db | 混后峰值 |
|---|---|---|
| `whoosh` | -6 ~ -4 | -12 ~ -10 dBFS |
| `impact` | -6 ~ -3 | -12 ~ -9 dBFS |
| `pop` | -8 ~ -6 | -14 ~ -12 dBFS |
| `tick` | -12 ~ -8 | -18 ~ -14 dBFS |

`whoosh` 是弥散噪声，峰值和 RMS 差 15dB，所以它**天生不会在"按能量尖峰数音效"的机器指标里出现**——听感上它在，机器上它不在。
要机器也数得到，得靠 `pop`/`impact` 这种瞬态，或者把 whoosh 压到 0.1s 以内。

## 五、怎么混

```bash
scripts/mix_sfx.py --audio work/audio_norm.wav --cues cues.json --out work/audio_sfx.wav
```

- **不用 `ffmpeg amix`**：amix 默认 `normalize=1`，按输入条数把每条都压一遍，贴 4 处音效人声整体掉 12dB。这里是把音效先贴进一条等长空轨，再 numpy 直接相加，人声一动不动。
- 混完打印：贴了几处（逐条给时间/名字/增益/实际峰值）、主轨峰值、混后峰值、削波情况、时长和声道数。**时长与原轨 sample 级一致**，不会因为加音效把声画拉脱。
- 峰值硬顶默认 `-0.1 dBFS`：人声轨已经贴着 -1 dBTP 时，硬顶再严只会把音效压没。超顶时**只压音效床**、不动人声，并打印压了几 dB。
- 同一份 cues 重复跑，输出字节一致（无随机量），可以放心进缓存。

## 六、这一层的已知"假"点

按容易被听出来的顺序：

1. **whoosh 是滤波噪声，不是真拟音。** 真风声有湍流、有空间感；合成的只有一条干净的带通扫频。静场里给一记很清楚，压在连续人声底下会显得像"嘶"。
2. **四个音是四条固定素材。** 同一支片里 3 记 whoosh 完全一样，连着听第二次就露。真剪辑师每条都换样本。要缓解只能一次生成多个种子变体（现在没做）。
3. **pop/impact 的低频在手机扬声器上会消失。** 62Hz 和 40Hz 那两个成分，外放听不到，只剩咔哒——所以在需要"看得出来"的场合（竖屏、外放），pop 的高频咔哒才是主角，低频是给耳机和会议室音响的。
4. **tick 只有 50ms，AAC 低码率下容易被编码器吞掉。** 成片走 128kbps 以下时，它可能只剩一点点相位噪声。
5. **没有响度一致性。** 四条素材都归到 -6dBFS 峰值，但 RMS 差 12dB（`tick` -27、`pop` -16），所以同样的 `gain_db` 不等于同样的听感响度，得按上表分别给。

# MG 库：代码画的动效卡

**MG（motion graphics）** 在这里指的不是「加个动效」，而是**用代码画出来的一屏信息**：
数字、步骤、对比、术语。它跟实拍素材是互补关系——素材里没有的东西（规模、数量、因果结构），
只能靠画。

## 三层各管什么

| 层 | 决定 | 文件 |
| --- | --- | --- |
| 剪辑方案 `plans/*.yaml` | 骨架与节奏：这一格该长该短、该快该慢 | 不管 MG |
| 包装包 `packs/*.yaml` | **允许用哪几种 MG**、长什么样（tokens）、停在哪 | `mg.library` / `mg.rules` / `card.mg_top_h` |
| 时间轴 `timeline.json` | 这一格**具体用哪张 MG**、卡上写什么、锚在哪个词 | 元素上的 `card` |

一句话：方案管「什么时候该有一张卡」，包管「这张卡能长成哪几种」，时间轴管「这一张写什么」。

## 五种卡

| id | 长什么样 | 什么时候用 | 必填字段 |
| --- | --- | --- | --- |
| `keyword-big` | 一屏大字，单排、撑 70% 宽；可选压在人物脑后 | 一句话结论、强断言、要人记住的那几个字 | `text` |
| `stat` | 巨大数字 + 单位 + 一行说明 + 出处角标，数字从 0 滚上去 | 规模、金额、面积、数量、时长、比例 | `data.value` `data.unit`；`data.label`；`data.source` 或 `data.approx: true` |
| `steps` | 01/02/03 三个短条目，逐条滑入 | 两到三步的流程、并列条件、先后顺序 | `data.items`（≤3 条） |
| `versus` | 左右两栏 + 中缝 VS 弹出，可选尾句 | 两个时段、两个方案、两个做法的对比 | `data.left{head,body}` `data.right{head,body}`；可选 `data.tail` |
| `term` | 一个词 + 一句释义，释义后出 | 行话、方言词、品类词第一次出现 | `data.term` `data.def` |

## 选卡顺序（信息修辞同构优先，形状即语义）

> 完整广电包装与认知负荷准绳见 [editorial-packaging-principles.md](editorial-packaging-principles.md) 第二部分。选卡严禁只看「有没有数字、有没有两个词」机械套模板，必须先判**这句话的修辞关系**：

1. **局部占整体比例**（「六百平里厨房占两百平＝三分之一」）→ `proportion`（比例切分条；在未扩展前若暂用 `stat`，必须在 `label` 写出比例换算）
2. **单一量级证明**（「花咗三百万」「三十六小时完工」）→ `stat`
3. **真假/优劣对立交锋**（旧做法起壳 vs 新做法打磨）→ `versus`
4. **时间接力 / 全时段互补**（「朝早手工早茶，晚上桑拿鸡」）→ `day-night`（时段接力卡；**严禁误用带 `VS` 圆章的 `versus` 把自家互补业态画成死敌 PK**）
5. **先后工序或递进条件**（第一步→第二步→第三步）→ `steps`
6. **并列招牌 / 实物清单**（「虾饺、排骨、凤爪、叉烧包」）→ `chips`（名牌矩阵逐枚点亮；**严禁拿解释生僻词的 `term` 词条卡去解释大众熟知菜名**）
7. **外行听不懂的行话/方言概念**（「乜嘢叫吊水鱼」）→ `term`
8. **一句定乾坤的强结论** → `keyword-big`（把这句话压成 4–9 个字）

## 卡要看得完，也要说得出东西（2026-11-12 定）

Jerry 的原话：「srt-motion-cards 的卡还是用的不好，出现的太短，观众都没有看完就切了，
而且也都是生搬硬套的卡，内容关联度都不高，所有的内容都是要来真实辅助到片子的叙事主线的！」

这两句拆成四件可判的事，全部有脚本兜着：

### 一、时长按内容量算，不按格子长度算

| | 下限 | 上限 | 怎么算 |
| --- | --- | --- | --- |
| 信息卡（stat / steps / versus / term） | **2.6s** | 4.5s | 卡上所有要读的字折成展示单位（中文 1、拉丁 3 个算 1），÷ 7 单位/秒 + 0.6s 入场 |
| 大字（keyword / behind） | 0.9s | 2.4s | 还是 `emphasis.hold_s`，四五个字本来就一两秒 |

**卡允许跨格活着**：一句 2.1 秒的话配一张要 2.6 秒才读完的卡，不管下限怎么调都会漏字。
渲染层每张卡就是一条独立的 overlay clip，`start/end` 不受元素边界约束；
排卡时按先来先到，前一张不够长就把后一张往后推，**不许把前一张掐短**——被掐短的那张
正是观众没看完的那张。相邻两张卡之间留 0.2s，否则画面在打架。

以前这里的 bug：`card_windows` 在锚词分支里用 `st1 - start + 0.25` 反算时长，
锚词一短（「十个人」0.5s）卡就只剩 1.0s——所有卡都是 1.00s，就是这么来的。

### 二、卡的每个要素都要有词证

`scripts/check_cards.py` 拿这句口播的词级真值逐个对：

- `stat` 的**数字**必须在窗口里说过（中文数字也会折算：「两百平」「廿五张」「十一个人」）
- `versus` 的**左右两边**都要在窗口里有着落
- `steps` 的**每一步**都要在窗口里有着落
- `term` 的**词**要在这句里说全

判出来的是真事：曾经有一张 `versus`，左边写「另一种」，口播里只有「吊水鱼一种」——
那半边是我编的。观众会觉得字和话不是一回事，因为确实不是。

### 三、不许复述

`stat` 的 `label` 必须带来窗口里没有的信息（新实词 ≥ 2 个）。口播说「两百平厨房」，
卡再写一遍「两百平的厨房」，观众没得到任何新东西，只是把听到的字看了一遍。

合格的 `label` 长这样：
- 「三百万换六百平 —— 每平方米砸进去五千」（一个换算）
- 「不是浪费 —— 手法先要有地方落，出品才稳」（一个因果）
- 「占整层三分之一，唯一不留余地的花法」（一个判断）

### 四、卡跟着叙事走，不跟着格子走

数量 = 主线上有几个**转折点**，不是「有几段带数字」。密度按每 18 秒最多一张卡，
占屏不超过全片 25%。一条 51 秒的片子 3 张，62 秒的 3 张。

一条片子的卡应当连起来能读出主线。欧阳那两支的实际落法：

- a 片（钱花在哪）：600㎡ 换三百万 → 200㎡ 占三分之一 → 朝早茶 / 晚桑拿鸡
  （钱 → 最大那块 → 一天的用法）
- b 片（厨房为什么大）：200㎡ 不是浪费，是手法要地方 → 四大天王（行话解释）
- c 片（进门看到什么）：岭南元素（行话解释）

## 硬规矩

1. **一批片子里同一个卡型不重复超过 2 次**。三条 `stat` 连着出，观众会以为你在放 Excel。
2. **每条片至少一张内容专属卡**：有数字就必须有一张 `stat`，有对比就必须有一张 `versus`。
   全是 `keyword-big` 等于没做 MG，只是把字幕放大了一遍。
3. **卡上的话必须是台词里的原词**，不许另写宣传语。卡是「把说过的话画出来」，不是「再创作」。
4. **数字必须有出处**：讲得出是谁说的、哪一天说的，就写 `source`；讲不出来就 `approx: true`，
   画面右上角会自动挂「示意」。数字卡骗人比没卡更糟。
5. **图底主权与三种合法叠加态（绝对禁止「挡脸杀」与「糊菜杀」）**：
   - 人脸五官（尤其眼鼻三角区）与美食/产品特写中心拥有最高空间主权，卡片与任一帧人脸框重叠率必须 `< 2%`；
   - 全产线只允许三种合法叠加态：① **轻量挂角态**（不压暗全屏，避开人脸与主体中心）；② **景深退后 / 画中画态**（重型卡登场时底片高斯模糊退后或缩为侧窗，正式移交主权）；③ **整屏纯底切出态**（切走实拍 2–3s 在品牌色底板上纯粹呈现）；
   - **严禁在清晰未退后的露脸口播（`medium: talking`）或菜品特写正中直接盖 90% 黑遮罩大卡**；
   - 位置**不再**由一条写死的百分比带（旧：`21%–62%H`）决定，由 `scripts/card_layout.py` 逐卡按人脸框算（见下节「叠加态」）；
   - 这几条不是口号：`scripts/check_overlay.py` 逐卡重算 IoU（不采信渲染器写的数），渲前拦停，error 退出码 7。
6. **双通道去重（重卡在场退同期声字幕）**：一屏只留一处文字焦点——同一格里 MG 卡和大字撞了，大字让开（记 `deferred_to`）；重型 MG 卡（`stat`/`proportion`/`day-night`/`versus`/`steps`/`term`）在场期间，**底部同期声字幕必须自动挂起（记入 `suppressed`，写成带卡 id 与理由的列表）**，由卡内元素踩词渐进揭示，严禁上下两套字同时抢眼球。轻量大字（`keyword` / `keyword-big` / `behind`）不触发退字幕。
7. **视觉语域对齐（零硬编码底色）**：渲染器严禁写死冷黑蓝弹窗底 `rgba(10,13,19)` 或荧光柠檬黄；底板、遮罩色温、强调色、圆角、字体 100% 走 `packs/*.yaml` 的 `tokens`（餐饮茶楼走暖食烟火色板，绝不把粉嫩食材压成生冷灰暗色）。

## 时间轴写法

```json
"card": {
  "kind": "stat",
  "text": "两百平",
  "on": "两百平",
  "data": {"value": "200", "unit": "㎡", "label": "纯手工厨房，占总面积三分之一",
           "source": "牛哥口述 · 2026-10-22"}
}
```

- `on`：锚词，卡必须晚于它发音 +0.15s 出现（声音先出，画面跟着）。
- `data`：只有 MG 卡用；`keyword-big`/`behind` 只写 `text`。
- 卡的**时长**不写在时间轴里，由渲染器按内容量算（见下一节）：锚词只决定「什么时候出」，
  不决定「放多久」。

## 渲染实现

`scripts/render_hf.py`：`MG_KINDS = {"stat","steps","versus","term"}`，HTML + CSS 变量 + GSAP
逐件入场（数字滚动、条目错位、VS 弹出、释义后到）。颜色、圆角、描边全部走 `tokens`，
换包不用改代码：`tokens.palette.accent` 一改，五种卡一起换脸。

## 叠加态：卡放哪由这一格的画面决定（T-019）

旧做法只有一种态：`.mgwrap::before` 铺满整屏的 radial 暗场 + `.mg` 钉在 `card.mg_top_h`
到 `0.62H` 之间那条带。第五轮对抗式审查在成片上抓到三处直接后果——`VS` 圆章正贴在主讲人
两眼之间、`200㎡` 把脸压成一块黑板、「四大天王」黑膏药盖住菜盘上半截——而当时 8 道脚本全绿：
**没有任何一道判据知道人脸在哪**。现在「卡放哪」由数据决定，不由百分比决定。

### 数据源：`hf/work/faces/<clip>.json`

`scripts/native/person_mask --faces <clip> <start> <dur> [fps]`（同一个二进制，旧的遮罩调用
一个字没动）用 macOS Vision 的 `VNDetectFaceRectanglesRequest` 逐帧出人脸框，JSON 打到 stdout：

```json
[{"t":0.5,"x":0.3923,"y":0.2764,"w":0.2371,"h":0.1333,"conf":0.87}]
```

坐标归一化、**原点左上**（Vision 原生是左下，工具里已经翻过），`t` 是相对该片段起点的秒数。
渲染器把它缓存进 `hf/work/faces/<clip>.json`（片段比缓存新就重算；二进制换了也重算）。

> 竖屏素材常存成 1920×1080 + 旋转 90°，`AVAssetReader` 吐的是**存储方向**的像素——不把
> `preferredTransform` 共轭进 CIImage 坐标系（`T' = F∘t∘F`），检出来的框会安静地错
> （实测：人脸跑到画面 67% 高度、x 却看着对，框住的是背景与左肩）。拿已经切好的
> `hf/clips/*.mp4` 去跑没有这个问题（那些片段本身就是正的）。

### 判据与输出：`scripts/card_layout.py`

输入：卡的种类（自然尺寸）、这一窗口内所有帧的人脸框、该格介质（`medium`）、
人占画面比例（`hf/work/pstats/` 的遮罩统计）、字幕带位置。
输出 `layout_mode` + 卡框 + 底衬框 + 模糊半径：

| mode | 什么时候选它 | 底片怎么处理 | 卡 |
| --- | --- | --- | --- |
| `corner` | 轻量卡；或重型卡但找不到够大的合法区 | **一点不压暗**，只在卡背后垫一块羽化局部底衬 | 缩进合法角/边（`scale` 0.52–1.0） |
| `focus_blur` | 重型卡登场、底片是实拍 | 底片 `backdrop-filter: blur(22px)` 退后 + 局部半透明底板 | 占最大合法区，**仍然避脸** |
| `cutaway` | 没有人脸、或该格 `medium != talking`、或卡 ≤2.5s 且前后都是 B-roll | 整屏切到品牌底板（`palette.ground` 打底 + `tokens.surface.plate` + 包的遮罩两层叠上去） | 居中整屏图形 |

硬红线（写在代码里，不许配置）：`medium: talking` 且人占画面 ≥15% → `cutaway` 直接不允许；
任何 `corner`/`focus_blur` 的卡框与任一帧人脸框 IoU 必须 `< 2%`（搜索时还额外给脸框加 2% 余量，
抵掉跳切推近带来的位移）。找不到合法位置时降级并记 `degraded: true`，交给闸门判红——
**不假装摆下了**。

底衬也跟着卡走（B10）：`corner` 是卡框外扩 3%W/2.2%H 的一块羽化板，`focus_blur` 是横向铺满、
纵向以卡为中心的一段羽化带，`cutaway` 才是整屏。**没有任何一种态会铺一块 90% 黑去压全屏。**

`cutaway` 的底板是**两层**：`palette.ground` 打底、`tokens.surface.plate` 与包遮罩叠在上面。
只铺 ground 一层会把整屏压成近黑（实测 L≈0.10，正好掉进 `blackdetect` 的 0.10 阈值，
验收会报「黑帧 1 段」）；叠上底板色后 L 回到 0.2 以上——切出的是「品牌底板」，不是「黑屏」。

结果写进 `out/cards.json` 的每张卡：

```json
"layout": {"mode": "focus_blur", "box": [0.04, 0.56, 0.8, 0.34],
           "plate": [0.0, 0.538, 1.0, 0.384], "box_px": [43, 1075, 864, 653],
           "blur_px": 22, "scale": 1.0, "face_iou": 0.0, "face_src": "vision",
           "cover": 0.3704, "media": ["talking"],
           "face_refs": [{"clip": "…", "offset": 0.0, "dur": 4.98}],
           "why": "重型卡；底片模糊 22px 退后 + 局部底板，人占画面 37%", "degraded": false}
```

人工要覆写就写时间轴的 `card.layout`（`mode` / `box` / `plate` / `why`），
详见 [timeline-schema.md](timeline-schema.md) 的「card.layout」一节；**闸门不豁免**。

### 重卡退字幕：`out/subs.json` 的 `suppressed`

重型卡的时间窗内，底部同期声字幕自动挂起（B9 同屏单焦点）。`suppressed` 是**列表**，
每条记「哪张卡（`card`）/ 哪一句（`cue`：起止与文字）/ 重叠多久 / 为什么」：

```json
"suppressed": [{"card": "mg-01", "kind": "stat", "card_window": [4.078, 8.345],
                "cue": {"start": 4.98, "end": 5.94, "text": "我哋一共有四个"},
                "overlap_s": 0.96,
                "reason": "重型 MG 卡在场，同期声字幕挂起（B9 同屏单焦点）"}],
"subtitle_suppressed": false
```

- `suppressed` 只记「被重卡挂起的那几条」；整层字幕关掉（`subtitle_system: none`）记在
  `subtitle_suppressed: true`，两件事不混用一个字段。
- 一条字幕只要与卡窗重叠 ≥0.15s 就整条挂起（不切条：切条会把半句留成残字）。
- `cues` 仍是**全量真值**（说了什么），挂起的是「这一屏故意不写」——所以字幕密度、
  漏字类判据不受影响，但「字幕烧进画面」类判据会跳过被挂起的那几条。

### 闸门：`scripts/check_overlay.py`

```bash
python3 scripts/check_overlay.py --project <项目>     # 0=过；1=有 error
```

三条判据（每条都**自己重算**，不拿渲染器写在 `cards.json` 里的结论当证据）：

1. `①` 每张卡与窗口内任一帧人脸框的 IoU < 2%（人脸来自 `hf/work/faces/*.json` 原始读数）；
   缺人脸数据 → warning 并说清是哪一段没量到，**不当它通过**；
2. `②` `medium: talking` 且人占画面 ≥15% 的格子上出现整屏暗场 → error
   （人占比从 `hf/work/pstats/` 的遮罩重算，不是读声明）；
3. `③` 重型卡窗口与字幕重叠 ≥0.15s、但 `suppressed` 里没有这条留痕 → error。

另外一条附加守卫：`cutaway` 只许用在「没有人脸 / 非口播格 / ≤2.5s 且前后 B-roll 承接」的格子上
（B7 的第三种态是**切走**，不是「在口播近景上蒙一块板」）。
`render_hf.py` 渲前自动跑它，有 error 直接退出码 **7**（与 5 声音在前、6 卡准入并列）。
负样本回归：`python3 scripts/test_overlay_judge.py`（压脸 / 口播整屏暗场 / 重卡撞字幕三红 + 合法卡零误杀）。

### 现在检不出人脸的条件（如实计）

Vision 的 `VNDetectFaceRectanglesRequest` 在下列情况会**一帧都不给**：侧面/低头超过约 60°、
戴口罩或大面积遮挡、严重欠曝或逆光剪影、远景里人脸小于约 30×30px。此时 `faces` 为空但
`face_src` 仍是 `vision`（意思是「量过了，没有脸」）——`card_layout` 会**允许** `cutaway`，
因为画面上确实没有人脸要做主权让位。若连工具都跑不起来（缺编译产物、解码失败），`faces_of`
返回 `None`、`face_src = missing`，此时 `cutaway` 一律不允许（不知道就别切走），`check_overlay`
报 warning 说明「哪一段没量到」——不会静默当成「没有脸」。

### 卡面语域：`tokens.surface`

`accent` 管的是「强调什么」，管不了「卡这一块底长什么样」。底板、遮罩、描边、卡面字色
单列一栏 `tokens.surface`——**这四样过去写死在渲染器的 CSS 字符串里**，换包换不掉：
拿冷黑蓝弹窗底 + 90% 全屏黑遮罩去包广式早茶，虾饺被压成隔夜菜的颜色（2026-11-13 T-018 事故）。

| 字段 | 必填 | 作用 | 写作要点 |
| --- | --- | --- | --- |
| `plate` | ✓ | 面板底（`versus` 两栏） | 语域色 + 透明度，如暖食 `rgba(92,54,26,.90)` |
| `plate_term` | | 词条卡底 | 字多面积小，一般比 `plate` 再实一成；不写就等同 `plate` |
| `border` | ✓ | 面板描边 | 描边颜色也要跟语域走（暖食走暖白/金，不走中性白）；亮到能一眼看出卡沿 |
| `border_term` | | 词条卡描边 | 不写等同 `border` |
| `scrim` | ✓ | 整屏暗场 | 写**完整 CSS 背景**（`radial-gradient(...)` 整串），才能表达「只局部柔化、边缘归零」 |
| `ink` | | 卡面字色 `#RRGGBB` | 深底浅字；纸感这类浅底包不能跟 `palette.ink` 混用 |
| `blur_ness` | ✓ | 面板磨砂（`backdrop-filter` 半径） | `0` = 不磨砂（`none`，像素不动），> 24 会把底片糊成一片 |
| `shadow` | | 面板外投影（可带一道内侧顶光） | 缺省 `none`（像素不动）。大半径 + 低不透明度 + 暖色，**不要硬边** |
| `term_pad` | | 词条卡内边距 `[上下, 左右]` | 缺省 `[30, 26]`（旧值）。删内框时别把面板的呼吸一起删了 |
| `term_gap` | | 词头与释义的行间（px） | 缺省 `22`（旧值）。词条卡的「词」与「释义」要能分开读 |

两条硬规矩：

1. **渲染器不再自带语域。** 包没写 `surface` 就退成中性深灰黑，不替谁表态。
   `check_packs.py` 对 `scripts/render_hf.py` 源码做静态断言：再出现冷黑蓝卡底
   （`#0A0D13` / `#0C0F15`）或非等比 `scaleX()` 直接判红——防的是「下次顺手写回去」。
2. **遮罩浓度是「读不读得出来」的账，不是风格账。** 换语域只换色温；
   把 `.90` 降到 `.52` 就等于把文字对比度抵给背景了，得同时把 `plate` 加实。
3. **面板要「浮起来」，不能只是「画在背景上」。** 判据是可量的：面板内与紧贴边外的明度差
   （L = 0.2126R+0.7152G+0.0722B）**要为正、且面板明显亮于贴边阴影带**。
   同色系底板 + 同色系遮罩最容易犯的错就是「深棕底漂在暖棕背景上」：P4 一轮复核时
   面板内 L=27.5、贴边 L=53.6（−26，卡面比周围暗），像一块坑；改成
   `plate` 亮一档 + `shadow` 投影 + 亮一档的金边后，面板内 L=58.9、贴边 L=42.5（+16.4）。

现成四包：`P1-warm`（暖实拍，暖炭灰卡面）、`P2-paper`（纸感）、`P3-dark`（深色科技，
承接原来的冷黑值）、`P4-canton-warm`（暖食烟火：琥珀深茶棕底板 + 暖金/朱砂 + 暖色外投影）。

```bash
python3 scripts/render_style_preview.py --pack P4-canton-warm --mg
# → styles/previews/ 下三张 1080×1920 卡面：P4-canton-warm-mg-stat.png / -term.png / -versus.png
```

`--mg` 那三张不是样张（样张是 Pillow 画的，只验色调与版式），是**真上浏览器**截的卡面：
底板不透明度、遮罩把亮部压了多少、描边在不在，只有像素能证。

## 验收

- `check_cards.py`：时长 / 相邻 / 早于锚词 / 密度 / 占屏 / 词证 / 不复述，七类判据。
- `check_overlay.py`：叠加态三判据（压脸 / 口播整屏暗场 / 重卡撞字幕）+ cutaway 合法性。
- `check_packs.py`：包里的 `mg.library` 必须都是渲染器认识的 kind。
- `verify_film.py`：`out/cards.json` 里每张 MG 卡都要真的在画面上（三帧采样，按 `layout.box_px`
  的实际位置取色，不是看声明）；报告里单列「叠加态」一项。
- 目测：抽帧看卡有没有压脸、压字幕、卡上的字有没有被背景吃掉。

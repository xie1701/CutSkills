# 素材库怎么管

目标只有一个：**素材越攒越多、越来越旧、越来越散（本机 / 移动硬盘 / 网盘），但你永远能找到「那一段」并且知道它能不能用。**

答案是「文件不动，索引动」。这份文档讲清楚为什么，以及真要做的时候怎么做。

## 一、可以改名，但要走脚本

原始文件名是相机给的编号，人看不出内容——所以**该改**。但改名有两个前提，不看这两条一定会出事：

1. **先有索引**（`uid` 内容指纹），否则改了名就没人认得这是哪个文件了；
2. **改走 `rename_assets.py`**，它会同步写映射、更新索引、跟 L2 记录。用 Finder 批量改名或 `mv` 完不管，引用就断了。

```bash
rename_assets.py --library "<库>"                           # 演练（默认），不落地
rename_assets.py --library "<库>" --apply                  # 真改
rename_assets.py --library "<库>" --apply --fix-projects    # 顺带改项目里引用的路径
rename_assets.py --library "<库>" --revert                 # 撤销最近一次
```

命名规则 `YYMMDD_批次_内容_级别_原编号.EXT`，细节见 [../SKILL.md](../SKILL.md) 的「命名」一节。三条硬规定：

- **日期拿不到就写 `无日期`，不猜。** 容器里的 `creation_time` 不可全信（相机时钟会错）；文件名里有日期则优先用文件名。
- **内容词只来自 L2。** 没跑过 L2 的素材宁可空着。所以最佳时机是 L2 覆盖得差不多了再一次改到位，否则补一条 L2 就要重改一次名。
- **原编号必须留在末尾。** 否则对不回相机/手机，也对不回别人手里的同一份。

## 二、索引靠三个身份认人

| 字段 | 用途 | 改名/搬家后的表现 |
|---|---|---|
| `uid` | 内容指纹（文件大小 + 首尾各 4MB 的哈希，形如 `a3f9c2e1b704`） | **不变**。重扫时按 uid 认出「还是那个文件」，把新路径接上，旧路径进 `aliases` |
| `legacy_key` / `legacy_path` | 第一次建索引时的路径哈希，用来命名缓存（缩略图、转写、切片） | **不变**。变了就得把全部转写重跑一遍——几小时的事 |
| `id` / `path` | 当前相对路径，给人看、给 grep 用 | 会变，这是正常的 |

一条命令让它自愈：

```bash
index_assets.py --library "<库>" --stage finish      # 全量重扫元数据，按 uid 认人，不解码不转写
```

命中旧素材时会打印 `~ 认得是老素材：旧路径 → 新路径`。

## 三、真要给别人看：副本 + 对照表

如果要把素材交给客户或外部剪辑，那条原则是「**母版不动，副本按规范命名**」：

1. 先跑一次 `--stage finish`，确保索引是最新的；
2. 拷到移动硬盘时按 `素材索引.csv` 批量重命名副本；或者直接给 `素材索引.csv` 配合整理好的母版；
3. 客户要的是「知道哪个文件是什么」，索引表 + 可读文件名两样都能给。

## 四、冷存储

`_cutskills/storage.json`：

```json
{
  "a3f9c2e1b704": {"where": "cold", "volume": "柒造备份盘", "note": "2026-12 归档"},
  "b71c0f2a9d33": {"where": "cloud", "service": "阿里云盘", "note": "原件 12G，云端留原片"}
}
```

索引的「位置」列会显示 `本机` / `冷存储·柒造备份盘` / `缺失（需找回）`。**缺了就是缺了，不许静默当成没有**——宁可报「需找回」，也不要在剪辑时用一段替代品糊过去。

迁移的判据（按顺序）：

1. 已经在成片里用过的段 → 留在本机（回改要快）；
2. `grade = must-use` → 留在本机；
3. 剩下的按 `huge` 标记和 `bytes` 从大到小往外挪，挪到本机只剩能用得上的那部分为止。

## 五、该备份什么

**`_cutskills/` 比素材更值得备份。** 素材丢了还能重拍；转写、L2 判断、分级、词表是花掉的时间和判断，重来一遍等于把这条路再走一遍。素材 13G，`_cutskills` 现在 260M——顺手一起同步到网盘。

## 六、日常维护

| 什么时候 | 跑什么 |
|---|---|
| 新素材进库 | `--stage l0 --jobs 3` → 有空再 `--stage l1 --l1-jobs 2` |
| 素材被改过名 / 挪过位置 | `--stage finish`（按 uid 自己认回来） |
| 转写错字多 | `lint_transcript.py` → 改 `lexicon.json` → `--stage rephrase` |
| 每月一次 | `--stage finish`，看一下 `素材索引.md` 里「位置」列有没有「缺失」 |

## 七、反面例子

- 在 `素材/` 里放 `新建文件夹 (2)`、`精选/`、`精选2/` —— 分了等于没分，索引里全是同级批次。
- 把成片和素材放一起 —— 成片会被当素材索引进去，`duration` 和分级全污染。成片放 `_cutskills/projects/<slug>/out/`。
- 用「最终版」「最终版2」命名素材 —— 信息量是零，而且第二天就不知道哪个是真的。
- 把 `_cutskills/` 加进 `.gitignore` 又删了 —— 索引没了可以重建，但转写和 L2 判断要重花钱。

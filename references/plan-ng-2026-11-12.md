## 一、三个决定的落地方式

### 1. 「十一月开业」删掉，用文字卡兜 ✅

删 `el14`（a 片）/ `#15`（b 片）这一格音频。信息改成 `stat` 卡挂在邀请那一段：

```
11 月  开业        ← 大字 + 小字「一千平 · 金湾」，source「牛哥口述」
```

好处不只是避开 NG：开业时间是**硬信息**，用卡比让人听一遍口误更清楚。
这条也顺势确立一个原则——**音频里说不清的硬信息，一律转成文字卡**，不要靠剪。

### 2. 字体：得意黑先用，另两只做备选 ✅

但**不能照抄 77px**。实测（1080 宽）：

| 字体 | 1 汉字 @100px | 10 字 @77px | 占屏宽 |
|---|---|---|---|
| 得意黑 SmileySans-Oblique | **88.1px** | 678px | 62.8%W |
| 思源黑体 NotoSansSC-Black | 100px | 847px | 78.4%W |
| 思源宋体 NotoSerifSC-Black | 100px | 847px | 78.4%W |

得意黑比思源**窄 22%**。同样写 77px，字幕会小一圈，观感和规范对不上——规范那个 77px
是相对他们自己的字体和画面算出来的数，不是通用常数。

改法：**字号由宽度反算，不写死。**

```
字号 = 目标单位宽 ÷ 字体宽度比
目标单位宽 = 屏宽 × 0.074     （10 单位 = 74%W，与现有 MAX_UNITS 判据同源）
```

落成 `styles/fonts.yaml`：

```yaml
fonts:
  得意黑:   { file: SmileySans-Oblique.ttf, ratio: 0.881, role: [subtitle, headline] }
  思源黑体: { file: NotoSansSC-Black.ttf,     ratio: 1.000, role: [subtitle, headline, body] }
  思源宋体: { file: NotoSerifSC-Black.ttf,    ratio: 1.000, role: [subtitle, headline, body] }
default: 得意黑
```

- 换字体不改代码：pack 里写 `subtitle.font: 思源宋体` 就行；用户在对话里说「换宋体」也走同一个键。
- `style_menu.py` 加一栏「字体」，三种各渲 6 秒静音微样片给他挑（第三维度的做法照旧）。
- 卡内长正文（MG 的 label、term 释义）**强制走 body 字体**——得意黑是斜体，长句读起来晃。

### 3. 大字抠像放脑后 —— 实测在这批素材上不成立，换方案 ⚠️

你说「尽量干净」，我先去验了能不能干净。**结论：不是抠像精度问题，是构图问题。**

实测 `152624` 那一帧（牛哥正面口播）：

- 人像 bbox：y **14.6%H** 起（头顶），横向 **0–100%W**
- 逐行覆盖：30%H 处人占 **34.8%W**，65%H 处占 **93.4%W**
- 字要撑 70%W 才够分量，人比字还宽

所以「字在人后」= 字被脑袋拦腰截断。我把合成图给视觉模型看过，原话：

> 「'间'字右半被头部遮挡，'高'字大部分被左脸/肩膀遮挡……**不能直接使用，属于明显露馅级别**」

根子在：srt-motion-cards 自己的已知限制里就写着「大字抠像对发丝、逆光不稳定；**建议数字人素材**」。
牛哥是近景真人，正好是它的失败场景。

**替代方案（已实测，效果干净）：大字放头顶上方 + 顶部渐变压暗。**

- 位置由遮罩 bbox 反算：字底 = 头顶 − 1.5%H，字顶 ≥ 6%H（避开平台顶部 UI）
- 实测结果：字撑 70%W、114px、「空间高 先坐得舒服」完整可读，不压脸不压头发
- 顶部加 0→18%H 的渐变压暗（不透明度 ~60%），既压住背景的梁柱管道，又让白字跳出来
- 视觉模型评价：「遮罩过渡柔和，没有脏感，很好地起到了背景降噪的作用」

**抠像 behind 不废弃，改成条件启用。** 判据（全部可算，不靠眼）：

| 条件 | 阈值 | 不满足 |
|---|---|---|
| 人脸框宽度 | < 35%W | 走头顶大字 |
| 头顶留白 | ≥ 20%H | 走头顶大字 |
| 遮罩软边占比 | < 3% | 走头顶大字（发丝太乱） |

三条都过才启用抠像——数字人素材、中景、半身像会自动走这条路，近景大头自动降级。
这样以后不用每次人肉判断「这条能不能抠」。

## 二、这套东西凭什么「下次不再重蹈覆辙」

这是你问的重点。我把方案分成两类，逐条标清楚：

### 2.1 一次性修片（这次用完就没了）—— 尽量压到最少

| 动作 | 说明 |
|---|---|
| 改 a/b 两片的具体窗口 | 换 take、收窗、删段、重排结尾 |
| 重渲两条片 | 结果不可复用 |

### 2.2 产线规则（以后每条片自动生效）

| # | 规则 | 落地位置 | 拦住什么 |
|---|---|---|---|
| R1 | **`evidence` 不许手写** | `timeline.py`：`evidence` 只由词级真值生成；人只能提交「删除片段」的 diff，加字直接报错 | 这次 19–25s 的病根：我手写的美化稿把 NG 洗成了正片 |
| R2 | **take 择优** | 新增 `pick_take.py`：按口水数 / 口令数 / 空档数 / 相似度排序，取最高 | 「同一个论点 4–8 个 take，挑到哪个算运气」 |
| R3 | **句首非法** | `speech_hygiene.py`：首词 ∈ {然后, 所以, 因为, 就系, 咁} 或首字是上句尾 → 前挪或换 take | 现在多数段以「，就系」起头，观众听半句 |
| R4 | **接缝不重复** | 同脚本：前段尾 6 字 ∩ 后段头 6 字 ≥3 字 → error | 「回音」：`因为有咁` + `我有咁大嘅厨房` |
| R5 | **论点不重复** | 同脚本：相邻三段实词集合的重合度 > 0.5 → warning | el4/el5/el6 三段都在说「厨房大因为纯手工」 |
| R6 | **声音在前（四条全量）** | 新增 `check_timing.py`：卡起点 ≥ 锚词 +0.15s；元素 ≥ 自己台词 +0.12s；锚词找不到 = error；卡尾必须覆盖最后一个元素 | 现在锚词找不到只 `print` 一句，照样出片 |
| R7 | **字幕不许改词** | `subs.py`：书面稿 vs 真值做字符级 diff，只许删不许增；增字判 error | 「放心」「我哋」这种凭空造的词 |
| R8 | **字体宽度校准** | `fonts.yaml` + 反算字号 | 换字体后字号失准 |
| R9 | **behind 条件启用** | `render_hf.py`：三条 bbox 判据 | 近景硬抠像露馅 |
| R10 | **MG 时长按内容条数** | `card_windows()`：stat 1.8 / term 2.2 / versus 2.4 / steps `0.6+0.7n` | 一律 1.5 秒读完 |

### 2.3 让规则不腐烂的三件事

**① 每条判据配负样本。** 这次查出来的三段音频切成夹具存档：

```
references/negative-samples/hygiene/
  retake-glitch.wav      ← 「唔系唔系…」口误重来
  crew-ok.wav            ← 「o k o k」
  seam-echo.wav          ← 前后两段接出「因为有咁 / 我有咁大嘅厨房」
  repeat-same-line.wav   ← 「空间高先可以坐得舒服，空间感高先会坐得舒服」
  filler-tail.wav        ← 「因为咧，我觉得咧」
```

每条夹具在 `selftest` 里跑一遍，**必须红**。判据改坏了（变松）立刻暴露。
这跟 T-004 的教训一致：夹具可以造，但不能冒名顶替别人的评审。

**② 这两片进 golden。** `dianzan-a` / `dianzan-b` 各存一条基线（🟢/🟡计数），
谁改渲染链路把 NG 段又放回来、或把字幕改回 15 字，golden 立刻红。

**③ 准入线写进 `AGENTS.md`。** 在现有四条铁律后面加一条：

> 不许为了让片子过闸去放宽判据阈值。判据红了先看是片子的问题还是判据的问题，
> 片子的问题改片子，判据的问题要给出反例并同步改负样本。

### 2.4 判据自己的边界（不写清，以后一定误杀）

| 判据 | 依赖 | 会怎么错 | 应对 |
|---|---|---|---|
| 口水词 / 口令 / 空档 | 词级时间戳 | ASR 把「纯手工厨房」听成「纯土工期望」，但**词边界和空档仍然准** | 只用可数的量（时间、重复、词表），不判语义 |
| 重复检测 | 字符 n-gram | 真重复 vs 修辞式重复（「好正，好正」） | n ≥ 4 且间隔 < 2s 才算；修辞一般间隔短、字数少 |
| 字幕改词 | 书面稿 vs 真值 | ASR 同音错字会被当成「改词」 | diff 前先用拼音归一（`pypinyin` 已在 vendor），同音不算改 |
| 论点重复 | 实词集合 | 概念本来就该反复出现（「纯手工」是全片主题） | 只看**相邻三段**且**动作+对象**同时重合 |

这一节的意义：以后判据误报，不必重新发明，回来改这张表就行。

## 四、仍然搞不定的（诚实清单）

1. **「十一月」那条音频本身是废的**，删掉靠卡兜是取舍，不是修复。以后遇到同类（硬信息只有 NG take），
   规则是：能转文字卡就转，转不了就让客户重录，不要硬剪。
2. **ASR 对粤语工业词不稳定**（「纯手工」→「纯土工」、「煅烧」→「断烧」）。
   词表能兜一部分，但判据的召回率做不到 100%。所以最终防线还是**成片重新 ASR 一遍**这一步，它不能省。
3. **得意黑是斜体**，视觉模型认为实拍口播用思源黑体更稳。你要先用得意黑，我按宽度校准后渲——
   但如果成片看下来觉得飘，切回思源只改一个字段，不用我重做。
4. **抠像 behind 在真人近景上这条路我不建议再试**。三条判据会自动把它挡在门外，
   真要做，得先有中景/数字人素材。
5. **论点不重复只能判「重合」，判不了「顺序」**。结尾那种「开业 → 邀请 → 互动」的因果链，
   机器只能提示「这两段主题相同」，顺序对不对还得人看一眼。这个我不打算假装能自动化。

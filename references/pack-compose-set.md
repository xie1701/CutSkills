# 包装套怎么用 · 柒造（set-qizao）

`styles/` 目录下那五个 pack 的 yaml（pack-safe-talking、pack-paper-brand、pack-hud-monitor、pack-bilingual、pack-ui-narrative）是零件：A 安全口播、B 纸感品牌、C 监控壳体、D 双语双行、E 图文界面叙事，每个都写着它在参考片上量出来的参数带。
`styles/set-qizao.yaml` 是装配规则：说明这些零件**哪些能叠、叠的顺序、叠了之后谁让位**。

先把三个词说清，后面就不重复了：

- **pack（包装模板）**：一小包能直接执行的参数——字体族、字幕带位置、字高、描边或投影、节奏。一个 pack 内部不许混，混出来就是拼贴感。
- **layer（层）**：这里只有三层，职责互不重叠——**字幕系统**（字怎么排）、**壳**（画框边上有没有常驻信息）、**卡**（画面里有没有替观众搭结构的界面）。
- **beat（段落单元）**：`plan.json` 里的 `beats` 数组，一条片子切成几个段落，就是几个 beat。

柒造这套收 A、B、C、E 四个成员，**不收 D 双语双行**：目标观众是中文施工方与业主，第二行英文在这个交付链上没有接收方，而 D 的宽松档要永久让出 14–15% 画面。D 的模板本体仍在 `styles/pack-bilingual.yaml`，面向双语受众时单独取用。

合法叠法只有一句：**A 或 B 的字幕系统（二选一）+ C 的壳（0 或 1）+ E 的卡（0 或 1）**。

## 一、三条路，先选一条

| 路 | 什么时候走 | 怎么做 | 成本 |
|---|---|---|---|
| **手动选（人读表挑）** | 第一次做某类片子；素材情况特殊；你不同意自动结论 | 读第二节的八格表，指着格子说一句话 | 3 分钟 |
| **自动选（pick_pack）** | 判据清楚（有语音占比、时长、beats、有没有 card），想省事或想留个可复查的依据 | 跑一行命令，读它写的 `pack-choice.md` | 30 秒 |
| **不选（沿用上一次）** | 同一批素材、同一个系列、只是换一条片子 | 沿用项目上一次的 pack 名，不重新判 | 0 |

### 1. 手动选：人读表挑

八格 = 字幕系统 × 壳 × 卡。选的时候只回答三个问题：

1. **这条片子的主角是人的嘴，还是空间？** 嘴 → A；空间/材质/作品 → B。
2. **观众需要随时知道「走到第几步」吗？** 需要，而且内容确实是流程/教程/多章节 → 加 C。
3. **有没有一处事实必须并排摆出来才说得清？**（报价差、尺寸、前后对比、象限）→ 加 E。

三个问题都不确定时，宁可不加——**空着不丢人，贴错了才丢人**。

| 格子 | 组合 | 什么时候用（话术抄自各 pack 的 applies_to） |
|---|---|---|
| **A** | 只有字幕 | 单人坐姿口播、讲座、访谈精剪（机位几乎不动）；素材本身构图干净、不需要靠图形层解释 |
| **A-C** | 字幕 + 壳 | 工具实测、工作流演示、教程、多章节内容；素材含大量录屏/界面——本身就有「系统感」，壳是顺水推舟 |
| **A-E** | 字幕 + 卡 | 内容本身有「结构」可以画出来（步骤、象限、尺寸、进程），但只有两三处，不值得整片套壳 |
| **A-C-E** | 字幕 + 壳 + 卡 | 方法论、测评、清单、对比、改造过程，且长到需要章节定位（>300s 或 6 个以上 beat） |
| **B** | 纸感字幕 | 品牌/空间/质感类素材（家装、展厅、产品、面料）；有大量静止细节可看的长镜头；讲情绪、讲品味，不讲信息密度 |
| **B-C** | 纸感 + 壳 | 品牌长片、章节多到必须给路标。这套里风险最高的一格 |
| **B-E** | 纸感 + 卡 | 空间/材质类内容里有尺寸、对位、改造前后可画；纸感与纸片卡同源 |
| **B-C-E** | 纸感 + 壳 + 卡 | 三件事同时成立才用：品牌长片 + 多章节 + 有可画的结构。保留这一格是为了让禁忌可见，不是推荐 |

### 2. 自动选：pick_pack

```bash
python3 scripts/pick_pack.py --project "/path/to/_cutskills/projects/<slug>"
python3 scripts/pick_pack.py --project "<项目>" --library "<素材库>"     # 库不在项目上三级时显式给
python3 scripts/pick_pack.py --project "<项目>" --json                  # 机器可读，供别处调用
python3 scripts/pick_pack.py --project "<项目>" --no-write              # 只打印，不覆盖 pack-choice.md
```

它读三样东西：`intent.json`（audience / promise / duration_s / aspect / avoid）、`plan.json`（beats、段落、`card` 字段）、素材库的 `_cutskills/index.json` 里的 `counts`（`with_speech` / `assets` / `portrait`）。

五条规则，输出里会写清是第几条命中的：

| 规则 | 判据 | 动作 |
|---|---|---|
| 1 | `with_speech / assets > 0.4` 且时长 ≤ 180s | 字幕系统优先 A |
| 1 | 上面不成立，但内容属展厅/空间/材质/作品/案例 | 字幕系统 B |
| 2 | intent 或 plan 出现流程/步骤/教程/怎么做/几步/对比/测评，或有 ≥4 个 beat | 加壳 C |
| 3 | intent 里有数字对比，或 plan 里有 `card` 字段 | 加卡 E |
| 4 | 时长 > 300s 或 beats ≥ 6 | 加壳 C（长片需要章节定位） |
| 5 | 命中任一所选 pack 的 `fails_on` 关键词 | 降权，并把风险写进输出 |

结果写进 `<项目>/pack-choice.md`，里面有：选中的组合、命中的规则（带数字依据）、被否掉的选项及原因、风险、以及三条能直接粘的命令行。

**它判不了什么，必须人看一眼**（这些在 `pack-choice.md` 里也会写出来）：

- 素材主体是不是偏上（A 的 0.86 中心会落在手上/桌面上，C 的角标 13–14%H 会穿脸）。
- 单条素材撑不撑得住一张卡（E 的 `83s 长镜靠手工动作撑：素材撑不住就是死气`）。
- 缓动曲线、字体的具体名字——视频里只有结果没有参数。
- `avoid` 里写的东西有没有被真的避开。

### 3. 不选：沿用项目上一次

同一个系列、同一批素材、同一个说话人，第二条片子**不要重新选包**。重选的后果是同系列的两条片子字幕带一高一低、一条有壳一条没有，观众一眼看出发布混乱。

沿用的时候只需要说清一句：沿用哪一版。项目里留着的证据有两处——`intent.json` 的 `style_pack` 字段，和上一轮生成的 `pack-choice.md`。两者不一致时以 `pack-choice.md` 为准（它是判过的结果，`style_pack` 是项目初始化时的默认值）。

## 二、什么时候该换包

只列**可观测**的信号。没有证据的"感觉不对"不构成换包理由——换来换去比一直用错更伤系列感。

| 观测到 | 说明它指向 | 换法 |
|---|---|---|
| 观众说「字看不清楚」「字幕挡住手了」 | 字幕带压到主体，或亮底掉字 | A → A 的让位变体（带中心 0.86 → 0.69，纯描边不投影）；或换 B（带中心上移到 0.62–0.76） |
| 观众说「像 PPT」「全程在念字」 | 卡面占比过高，或节奏被卡拖住 | 减卡（留最必要的一两张）；仍闷就 A-E → A |
| 观众说「太素了，一点包装都没有」 | 内容其实有结构，只是没给路标 | A → A-C（前提是内容确实是教程/多章节；否则加了更廉价） |
| 片长越过 300s，或 beat 数到 6 个 | 长片需要章节定位 | 加壳 C |
| 素材类型换了：从坐姿口播换成展厅/空间/材质/作品 | 主体从嘴变成画面 | A → B（B 的镜头中位 8.5–11.4s，别再按 2–4s 剪） |
| 素材类型换了：从录屏/界面换成精致实拍 | 壳失去了「系统感」依据 | 去掉壳（A-C → A），或整片换 B |
| 素材整体变亮（白墙、亮白桌面、阴天外景） | 投影在亮底不够 | 用 A 但保留描边（`stroke` 2.5px @720h），不要只用投影 |
| 平台从横屏改竖屏 | 竖屏可用高度被壳吃掉 | 竖屏不要顶条；C 的 `usable_h_with_bar` 只有 0.86、`with_badge` 0.75 |
| 完播曲线在章节切换处掉坑 | 壳的信息太密或条目数不对 | 修壳，不要删壳：条目数写死是常见死法（7 步改 6 步立刻挤到不可读） |

一句话记法：**换的是「素材类型」和「观众要读的东西」，不是「这次想换个风格」。**

## 三、组合的禁忌（只写实测过的坑）

这些不是审美意见，每一条都在参考片或已有项目里出过事。

1. **A 与 B 的字幕系统同片混用。** A 是黑体 + 描边、带中心 0.79–0.92H、下沿距底 ≥5%H；B 是宋体 + 投影、中心 0.62–0.76H、下沿距底 ≥24%H。带位差 10–16 个百分点、字体族不同，同片混就是一条时间轴上跑两套字。
2. **C 的竖条和顶条同屏。** 顶条是 0–4.7%H 通栏（5–9 个条目），竖条是 5×21px 红竖条 @6.7–7.4%W 的章节锚点。两种都是「你在第几段」的指示器，同屏就是两条进度在打架。
3. **描边和投影叠在同一个字上。** 宋体描边会糊笔画（B 一律投影），黑体投影在亮底不够（A 可以用描边）。两者叠用的片子，字看起来永远脏。
4. **壳叠在精致素材上。** 双侧胶片齿孔 + 精致素材 = 双重包装，一眼就是套壳——这条是参考片作者自己记下来的，只适合「录制过程感强、可以显得糙」的素材。
5. **标注层进调色链。** E 的红标注（#D4231F）如果在调色之前叠，会跟画面一起被抽灰成灰粉。**图形层永远在调色之后。** 壳同理。
6. **卡面占片长过半还按 4.1s 中位剪。** 卡多 + 镜头短 = 节奏闷死；卡多时镜头要拉长，或者减卡。
7. **字幕带下沿进最后 5%H。** 五族里下沿最靠底的 E 已经贴到 4.5%H，竖屏改造会被平台底栏吃掉。加壳时以 C 的 `content_area` 为准。
8. **壳内条目数写死。** 7 步总览改成 6 步，间距立刻挤到不可读。步数变了要么改壳要么删壳。
9. **B 配信息密度高的内容。** 11.4s 中位 + 零音效，讲流程会像「卡住了」——B 的成立前提是讲情绪、讲品味，不是讲推进。
10. **B 配高饱和素材。** B 的 `saturation_cap` 是 0.20，实拍红木、花艺、霓虹会被压成灰片。这是这个家族的成立前提，不是可以调的缺陷。

另外两条不是"禁忌"但会误判：

- **音效当节拍器用。** 实测同一批片里音效密度从 0 到 8.5 处/分都有，「3–7 处/分」不能当鼓点指标。音效是标点，不是鼓点。
- **用像素启发式检测字幕。** 试过，失败：同一批片测出 1 条/分钟与 322 条/分钟两个极端，白底界面、白墙、白字卡都和字幕混在一起。字号、位置、字体只能靠看图。

## 四、出问题往哪查

1. `pack-choice.md` 里记着是**第几条规则**命中的，先复核那一条的依据数字对不对。
2. `pick_pack.py --project ... --json` 再跑一遍，看 `facts`（`speech_ratio` / `duration_s` / `beats` / `cards` / `luma`）是不是你以为的那样。
3. `styles/set-qizao.yaml` 的 `mutual_exclusion` 六条：混层、两种壳型、多层叠加、字幕下沿、描边投影、图形层顺序。
4. 参数的出处都在 `references/packaging-families.md` 和五个 pack 各自的 yaml 注释里。那里写着每一条数字来自哪支参考片——改参数前先读那支片。

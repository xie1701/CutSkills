# T-045 · keyword 大字第一次被量（压脸 / 可读性 / 单排宽度）

> 一句话：`check_overlay` 里那句「大字走 .kw 层，另有 top_h 规则，不在本判据内」，
> 让大字成了整条链路**唯一没有人量过位置与可读性**的一层。这一单补上三道量法、
> 把 `dianzan-c` 那颗压在脸上的字挪开，并把「隔离层」做成包 token。

## 一、先说三条与任务单不一致的实测（旧读数不可用）

任务单给的「事实」里，有三条我用 1080 原像素重量之后对不上，先摆出来：

| 任务单 | 实测（1080 原像素） | 说明 |
|---|---|---|
| 6.75s 横向 **85–90%W**（超口径） | 墨迹 `x 170–911`，**宽 743px = 68.8%W** | 「85–90%」是**右边界的 x 位置**（911/1080 = 84.4%），不是宽度。三张 keyword 卡实测 68.4 / 68.8 / 69.4%W，都落在 0.62–0.78 里 |
| 6.75s 视觉 **3/10**（字被背景吃掉） | 1080 原像素裁片重判 **8/10**（两轮）；可读性实测 ΔL(p10) **25.8**（门槛 12） | 与合格的 25.15s 那张（ΔL 29.3、8/10）同档。`dianzan-c` 旧片同位置我量到 24.1 / 29.3——**分不开**。所以「3/10、无隔离可读性差」这条**没有复现** |
| 10.74s 字压脸 | **复现，且更重**：字框 `y 585–679` 与人脸 `x .314–.526 / y .279–.398` 重叠 0.98% 画面面积（占那张脸 46%），字窗内 **3 帧命中**；视觉 **4/10**「字横跨人物眼部」 | 真红，已修 |

结论：**两颗字里只有一颗是真红**（压脸）。6.75s 那颗的问题不是对比度不够，是背景
**高频杂乱**——亮度差够（ΔL 25+），但工地的工具/管子/人把笔画切碎。ΔL 这条判据抓不到它，
这一点如实写在这里（见「还没解决」第 2 条）。

## 二、新增判据：`scripts/check_keyword_text.py`（渲前闸门，error 退出码 8）

挂载点：`render_hf.py` 里排在「声音在前(5) / 卡准入(6) / 叠加态(7)」之后，退出码 8。

| 判据 | 量法 | 门槛 |
|---|---|---|
| ① 压脸 | 大字**实际墨迹框** × 卡窗内每一采样帧的每一张脸（`card_layout.faces_of`，Vision 2fps，半格容差），重叠面积 > 0 | error（`KW_TOUCH_EPS = 0`） |
| ② 可读性 | 墨迹 vs **紧邻**背景的 ΔL（CIE L*、15×15 邻域中位、取笔画边缘 p10——`measure_panel` 同一套口径），背景取 `hf/clips/*.mp4` 里马上要合成的那几帧 | ΔL(p10) ≥ 12 |
| ③ 单排宽度 | 墨迹宽 ÷ 画幅宽 | 0.62–0.78 |

几何**只有一份**：`card_layout.kw_font_px / kw_ink_box / kw_top_of / kw_isolate / kw_pod_alpha`。
`render_hf.build_html` 画字调它们，判据量字也调它们。

字框是**真字体量出来的**（NotoSansSC-Black + CSS 行盒模型），不是「70% 宽」的估算。
预测 vs 成片实测（`--film`，花字色匹配 ∩ 预测字形外扩 10px）：

| 卡 | 预测框 | 成片墨迹 bbox | 差 |
|---|---|---|---|
| mg-01 睇下装修进度 | `[162, 589, 756, 123]` | `[170, 588, 744, 121]` | +8 / −1 px |
| mg-02 四张图，介绍布局 | `[164, 287, 752, 97]` | `[171, 286, 739, 96]` | +7 / −1 px |
| mg-04 鱼池有新鲜海鲜 | `[162, 586, 756, 105]` | `[165, 578, 759, 119]` | +3 / −8 px |

（横向 3–8px 是 advance 与墨迹的差；mg-04 的纵向 −8 是背景里那几点同色黄被外扩圈进来了。）

### 隔离层的两轮视觉复核里，mg-02 的那块板被撤掉了

第一轮：mg-01 加隔离 → 9/10「看不出一块板」；mg-02 抬到 0.165H → 9/10 但「字底与人头
间距偏紧、上方吊顶杂乱」。于是第二轮给 mg-02 也开了隔离 + 抬到 0.145H →
判词「衬底呈明显矩形轮廓，像一块后期色块」（那片是亮灰吊顶，压暗层看得见）。
**所以 mg-02 只保留位置修正，隔离层撤掉**；隔离层只给背景本来就暗、压上去看不出来的那几张
（mg-01）。这条也说明：隔离层不是「加了就好」，它得看底片亮度——包 token 只管长什么样，
画不画归卡自己（`card.isolate`）。

## 四、改了一条旧判据：`verify_film.text_band`（keyword 有卡框时按卡框量）

**判据错在哪**：`text_band("keyword", …)` 以前**无视**调用方给的框，永远回中段带
（28%H–76%H）。卡一旦按 `card.top_h` 挪到头顶，中段带里就量不到字——渲完第一遍
`verify_film` 直接报 🔴「大字烧进画面 10.7s 处花字色占比 0.00%」。

**负样本**：那一帧我量到 **28 800 个 #F6EB34 像素**在 `y 326–419`，字明明在画面上。
即：判据把「字在、但不在中段」判成「字没上屏」。

**改法**：有卡框（渲器落盘的 `cards.json.kw_box_px`，由 `build_html` 同一个函数算的）就以它为准，
四边留 24px；**没有卡框的老项目原样回中段带**（不退步）。松的那头没动：
`test_behind_band.py` 里「`box=None` 时 keyword 必须回中段带」的断言保留，另加一条正向断言。

`golden.py` 三条样片：`qizao-ground-01` 31/0/0、`qizao-protect-01` 29/1/0、`proj79` 28/1/3。
**`proj79` 的 3 条红在 master 上逐条相同**（`base = 828cd99` 独立工作树 A/B 过，diff 为空），
是基线（26/0）早于那批字幕判据的老账，不是这一单带来的——所以**没有** `--init` 重刷基线
（把红写进基线等于把它抹掉）。

## 六、还剩哪些没解决（如实）

1. **6.75s「字被杂乱背景吃掉」这层量不出来**。ΔL 只量「亮度差」，而这张字的问题是背景
   **高频纹理**（工具、管子、人）。要量它得加一条「背景局部对比度/边缘密度」判据，
   这一单没有做（任务单要的三条里没有它）。现在的处置是**视觉复核 + 隔离层**，不是判据。
2. **人脸判据看不见「人头/后背」**。`dianzan-c` 6.75s 的字框下半截压在人物**头顶**上
   （人物遮罩头顶 32.1%H，字底 37.1%H），但那一瞬间 Vision **没有检出脸**（2fps 首帧 0.80s
   才出框），所以判据对这张是绿的。要补得用人物遮罩的「头顶带」而不是脸框——另开单。
3. **`--film` 的可读性只报读数、不当判据**。成片口径靠颜色匹配找墨迹，背景同色（黄塑料筐、
   暖木、水反光）会被算进笔画或算进邻域。把这一层量对是 **T-044**（卡前/卡后帧间差分）的活；
   在它落地前，成片这条一旦判红就会把「背景偏黄的片子」一律判死，所以标成读数。
4. **`check_timeline` 仍是 1e/4w**（未变）：`#3 说「四张图」这一格没有对应视觉佐证`——
   库里 89 个素材逐个查过 0 命中「效果图」，任务单也写明不要去找。这条要人决定换 take 还是补素材。
5. **`proj79` 的 golden 基线是老的**（26/0 vs 现在 28/1/3，master 同读数）。要不要重刷基线，
   得有人拍板——重刷等于把那 3 条字幕红记成「已知」。
